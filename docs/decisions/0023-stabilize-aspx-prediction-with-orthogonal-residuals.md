# ADR-0023：以正交残差稳定求解 A-SPX 预测器

日期：2026-10-18。状态：已采用。

## 问题与独立依据

P86 的浮点协方差在近奇异输入上会丢失很小的残差信息。P87 再用接近的大乘积相减，
该误差可能被硬阈值放大为错误的滤波选择。
[稳定性调查](../ASPX_TNA_STABILITY_INVESTIGATION.md)的自有 f32 反例 b217 经精确有理数
求解，`|alpha0|=4.0000000007796116…`，按规范应双系数清零；旧生产得到
`3.9999999999916641…`，错误保留。对已舍入协方差做精确解算仍落在 4 以下，说明只提高
最后一次除法的精度不足以解决它。

该证据来自固定输入的数学解，未用 DRP 作为 oracle。378 个真实源子带窗口没有出现
此分类错误；本决策不将极限输入的问题说成整段参考 PCM 残差的主因。

## 决策

保留 `TS103190-1:v1.4.1:5.7.6.4.1.3–5.7.6.4.1.4` / P86–P89 与 ADR-0017
已经确定的数学目标，改用原始样本上的正交残差求解。令 `y=x[t]`、`x1=x[t−2]`、
`x2=x[t−4]`，`<u,v>=sum(conj(u)*v)`：

```text
p1 = <x1,y> / ||x1||²
p2 = <x1,x2> / ||x1||²
v = y − p1*x1
u = x2 − p2*x1
lambda = |<x1,x2>|² / ||x1||² * epsilon/(1+epsilon), epsilon=2^-20
alpha1 = −<u,v> / (||u||²+lambda)
alpha0 = −p1 − alpha1*p2
```

第一遍固定顺序计算所需投影，第二遍直接累加残差内积和能量。两遍都使用 P86 的
`t=4,6,...` 样本，不推进历史，不物化延长输入，不需要开方或堆分配。有限 f32 输入的
乘积及合法时隙累加均落在 f64 指数范围内，生产不需要宿主候选的幅度归一化。

第一延迟列全零时，按原零分母语义返回零系数；P86 的重叠时序也保证此时 `c02=0`。
残差分母为零时第二系数取零。被采样数据中的 NaN／Inf 在零列快捷返回之前拒绝，沿用
`NonFiniteCoefficient`，且不提交任何子带的部分输出。

本决策保留：

- 非负 ridge 目标、ADR-0017 的交叉项符号、每两时隙的采样及原始历史位置；
- 任一 f64 系数模达到 4 时双系数清零，随后收窄为 f32；不增加容差或存储后的二次钳制；
- 固定 f64 运算顺序，禁止 FMA／fast-math，目标侧零新增依赖及 `no_std`；
- chirp、预平坦化、QMF、音调初相、limiter、公共 API 与 CLI 的既有规则。

这是同一数学目标的数值实现修复，不是新参考兼容模式，也不是对规范正则项的否决。

## 测试与历史记录

先将 b217 的固定 84 个 f32 分量接入实际 `prediction_filters`，确认旧生产失败，再
替换求解器。新生产通过该回归及精确模长 4、静音、极端幅度、精确二次幂缩放、四分之一周
旋转、第二条正则正规方程与失败事务检查。

1,850 例独立 QR／有理数核对中的清零分歧从 1 变为 0，949 份精确幅度控制仍保持
逐位系数，9,250 份 HF 消费检查通过。ARM64／x86_64 的同输入重放逐字节一致。
恢复旧求解器、漏共轭、漏 ridge、吞掉非有限零列、把 `>=4` 改成 `>4` 均被判据捕获；
等价改写和恢复后的代码通过。

历史协方差闭式只保留在 `cfg(test)`，用于只有协方差、没有原始时序的旧诊断。
新重放明确标记 `orthogonal_residual`，无标记旧记录固定解释为 `legacy_covariance`；
不改名或重算此前调查结果。HF 重放中的协方差探针单独标明仍用历史闭式，真实时序路径
则直接验证新生产与独立增广 QR 的关系。

## 实际影响

378 份真实源带的 f32 系数逐位不变。8 种完整流、14 个选项组合的对象 PCM 与修复前
逐位相同，既定全区间／12–18 kHz 误差和峰值也保持；三层 36 条 PCM 基线无需更新。
这次收益是纠正已证明的数值边界错误，不宣称真实音乐的参考差分或听感得到改善。

完整构建、不同配置、优化构建确定性和性能 A/B 的结果保存在
[修复机器记录](../experiments/aspx_tna_stability_fix.json)。

默认／audio-decode／spec-tables 分别通过 516／1,328／107 项测试，相关 Python
114 项、两套 Clippy、格式和层审计通过；默认及音频 `no_std` 均在 thumbv7em 编译通过。
1,850 例的 ARM64 debug／release 输出也逐字节一致。

三份代表输入、Core／Full 两种模式做三轮交替 A/B，每轮每项固定五个完整 pass。
中位总耗时变化为 Core `−0.66%`、Full `−0.23%`，零 deadline miss；单项中最大增加为
bed 448K 的 Core `+1.50%`。这些幅度很小，只记为该样本中的性能基本持平，不作优化
收益或所有硬件性能的保证。
