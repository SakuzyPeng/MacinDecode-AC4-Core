# ADR-0012：搁置 direct-object，并重新锚定挂在它上面的条款

- 状态：Accepted
- 日期：2026-08-30
- 关系：重新锚定 [ADR-0011](0011-layer-syntax-decode-and-scene.md) 中以「direct-object
  完成后」为前提的四处表述，其余条款不变；不涉及 [ADR-0013](0013-extract-decode-crate.md)
  已完成的物理拆包

## 背景

M2 判定当前编码链只产出 A-JOC：`b_channel_coded = 0` 且 `b_ajoc = 1`，两个案例全部 143 帧
无例外。IMS profile 的发现推翻的是这条判定的**外推范围**而不是判定本身——那批产物是
channel-based（`b_channel_coded = 1`、`ch_mode = 6`、0 个对象、无 OAMD substream），
同样不含 direct-object。DME channel encoder 与 native IMS 又把真实矩阵扩展到
`ch_mode = 1/4/5/6/12`，仍然没有一条 direct-object。

至今没有任何真实 direct-object 码流。解析侧的分支由构造码流的单元测试覆盖，但那是分支覆盖的
下限，不构成对真实码流的验证——测试向量策略 9.2a 与 ROADMAP M5 都已写明这一点。

问题不在于缺口本身（缺口一直被如实记录），而在于**围绕它写下的路线**：ADR-0011 有四处条款以
「direct-object 完成后」为前提，ROADMAP 的「下一阶段」把它列为第 2 步。如果这个前提无期不能
满足，那些条款就永久悬空，读者会以为自己在等一件进行中的工作，而实际上是在等一份不存在的
素材。

## 决策

1. **无限期搁置 direct-object 的实现工作。** 不为无法获得的路径写投机实现，也不用构造码流
   冒充真实验证。
2. **M5 保持开放，状态改述为「已交付 A-JOC Core/Full 子集；direct-object 受真实素材阻塞而
   搁置」。** 不宣称 M5 完成——它的退出条件确实没有满足；也不拆分里程碑编号，编号变动不会
   让缺口消失，只会让历史难以对照。
3. **支持矩阵与 fail-closed 行为不变。** direct-object/mixed 继续显式拒绝。搁置的是实现，
   不是拒绝；把未验证路径悄悄放行才是本仓库反复警告的那类谎报。
4. **重新锚定 ADR-0011 中以 direct-object 为前提的四处表述**，见下节。ADR-0011 其余条款
   不受影响；本 ADR 不评判拆包顺序，物理拆包从来不以 direct-object 为前提（ADR-0011 决策 3
   即无条件），facade 阶段的取舍由 ADR-0013 自行记录。

## 对 ADR-0011 的重新锚定

四处表述的结论都不变，变的是**依据**：从「等一件进行中的工作完成」改为「等一个外部素材条件
出现」。这两者对读者的含义完全不同——前者暗示只要等就会到，后者说明该去找什么。

- **决策 4（OAMD 暂不成为独立 crate）**：「direct-object 完成后若出现可复用且无环的中间模型，
  再单独评估」改为取得真实 direct-object 素材后再评估。该条现在另有独立依据：`oamd ↔
  substream` 的互递归使 OAMD 无法在不制造环的前提下单独提取，与 direct-object 无关。
- **决策 6（FFI 继续延后）**：原文把 direct-object 与 Scene API、真实宿主所有权需求并列为
  前置条件。C ABI 的前置条件收敛为后两项，**不再把 direct-object 列为门槛**——否则一个可能
  永不到来的条件会无限期阻塞 ABI，而 ABI 的设计并不需要它。
- **「影响」一节「direct-object 完成前，OAMD 的最终可复用中间模型仍未冻结」**：按本 ADR，
  该模型无限期不冻结。这是现状陈述，不是待办。
- **「未采用的方向 / 立即建立 `audio-core`、`ajoc` 与 `oamd` 三个 crate」中「把尚未完成的
  direct-object 边界固化」**：论证不变，且因搁置而更强——「尚未完成」应读作「无限期未完成」，
  提前固化一条无法被验证的边界代价更大。

ADR-0011 背景段「但 direct-object 尚未完成」是写作当时的历史陈述，不在重新锚定范围内。

## 重新启动的条件

出现真实 direct-object 编码素材即可重启，具体指：新的编码器 profile 或版本产出
`b_channel_coded = 0` 且 `b_ajoc = 0` 的码流，或由外部提供此类码流，且能按 M1/M2 既有做法与
容器 sample table、参考解码器交叉核对。届时按 ADR-0007 的 Scene 边界补齐 identity/OAMD 语义与
公共输出门禁，关闭 M5。

## 理由

- 没有素材时写下的实现无法被判据裁决。本仓库用注入实验验证判据，而缺陷注入需要一条能观察到
  输出的真实通路；构造码流只能验证分支可达，验不了读法是否正确。
- 一条挂在永不满足的条件上的路标，比没有路标更坏。CLAUDE.md 已经记下过同类教训：没有结论时
  下一个人还会去看，有了假结论他就绕开了。把「等工作完成」改写成「等素材出现」，读者才知道
  该去找什么。
- M5 保持开放而非改判完成，保住了「不伪装成已覆盖」这条一贯写法；同时状态行说清楚已交付的
  子集，避免把一个已有实质产出的里程碑读成毫无进展。

## 影响

正面影响：

- ADR-0011 不再有悬空前提，读者能分辨哪些条款在等工作、哪些在等素材。
- C ABI 的前置条件收敛为两项可自主推进的事项，不被外部素材无限期阻塞。
- 路线图的「下一阶段」列表只保留真正可推进的方向。

代价与限制：

- M5 长期保持开放状态，里程碑完成度不再是线性推进的指标。
- direct-object 的解析实现继续留在代码里但无人验证；它受 fail-closed 拒绝保护，不会被误用，
  但也不应被当作「已实现」引用。

## 未采用的方向

### 按现有理解实现 direct-object 重建

规范条款可读，但没有真实码流就没有任何判据能区分「读法正确」与「读法自洽但错误」。跨实现
对照也不行——它只验证读法一致，两份基于同一段伪码的实现会一起错。

### 把 M5 改判为完成，direct-object 移入新里程碑

编号变动不会让缺口消失，反而让「M5 的退出条件是什么」在历史记录里出现两个版本。缺口留在
原处、状态说清楚，比重排编号更可追溯。
