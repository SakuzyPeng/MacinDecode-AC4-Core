# ADR-0002：标量重建的数值格式

- 状态：Accepted，第 3 条由 [ADR-0003](0003-trigonometric-tables-for-the-transform.md) 补充并局部修订，超越函数的约束由 [ADR-0005](0005-real-functions-without-a-math-library.md) 解除
- 日期：2026-08-13

## 背景

`5.1.3` 的量化重建分三步：DPCM 还原绝对标度因子、由标度因子得增益 `2^((sf−100)/4)`、反量化 `sign(q)×|q|^(4/3)` 后相乘。第一步纯整数，已实现（`asf::reconstruct`）。后两步与其后的 IMDCT（`5.5`）、A-SPX 合成（`5.7`）都要求实数运算，而当前状态有两条硬约束：

- **本 crate 实现侧至今零浮点。** 仅有的几处 `f64` 都在 `#[cfg(test)]` 里，用来给整数判据做浮点对照（`aspx::bands`、`aspx::syntax`、`aspx::frames`）。
- **`no_std` 下 `core` 不提供超越函数。** 实测确认 `abs`、`copysign`、`from_bits`/`to_bits` 与四则运算可用，`sqrt` 起就已不在 `core` 中，`powf`/`exp`/`ln` 更无从谈起。在运行期引入 `libm` 会打破工作区零外部依赖。（`5.7.6.4` 需要其中三个，ADR-0005 用 f64 级数在目标侧补上，仍不引入依赖。）

架构设计第 8 节要求「PCM 数值格式须在标量重建接口冻结前通过独立 ADR 确定」。本 ADR 落实该要求。

### 实测量级

八条向量、约 99 万条谱线：

| 量 | 规范全域 | 八条实测流 |
|---|---|---|
| `\|quant_spec\|` | ≤ 8 191（`5.1.3.1` NOTE 1） | 峰值 8 084 |
| `sf` | 0…255（`5.1.3.2` NOTE） | 77…159 |
| 增益 `2^((sf−100)/4)` | `2^−25`…`2^38.75` | 0.0186…2.76×10⁴ |
| `scaled_spec` 上界 | 7.6×10¹⁶ | 4.6×10⁹ |

实测峰值贴着规范上限，**因此反量化表必须覆盖完整的 `0…8191`**，不能按实测量级缩表。实测动态范围约 `2^38`，规范全域约 `2^81`——两者都远在 f32 的指数范围（`2^−126`…`2^127`）之内，所以选型的争点是精度，不是范围。

## 决策

1. **频域中间量、A-SPX 参数与输出 PCM 采用 `f32`。**
2. **变换与滤波器组的累加器采用 `f64`，写回时收窄为 `f32`。** 按不相关舍入误差估算，累加长度达 2 048 时，纯 f32 的舍入噪声约 `sqrt(2048)×2^−24 ≈ −111 dBFS`；满幅正弦下 24 位 PCM 的理论量化噪声约为 `−146 dBFS`，前者高约 35 dB。f64 累加把累加误差压回可忽略。
3. **一切超越函数在运行期由查表或位构造给出，目标侧不引入 `libm`，不依赖 `std`。**（构建期的取用范围由 ADR-0003 放开：`5.5` 的三角常量没有下面这种代数出口，改由锁定版本的 `libm` 生成并冻结摘要。）
   - `|q|^(4/3)`：`build.rs` 生成 8 192 项 `f32::from_bits` 常量表（32 KiB，进 `.rodata`），**生成过程不得调用宿主 `powf`**。对每个 `q`，生成器用 `u128` 精确比较相邻 f32 中点的立方与 `q^4`，按就近偶数规则选择位模式。按 `q = 0…8191` 顺序连接每项 `to_bits().to_le_bytes()` 后，SHA-256 必须为 `60b7347dff798930b6021357b9c7027234dd3455fac545aa02ff01eb4663a880`，不符即中止构建。该表是纯数学量，与 ETSI 附件无关，因此不受 `audio-decode` feature 约束，也不受分发限制。
   - `2^((sf−100)/4)`：拆为 `2^q × 2^(r/4)`，`q` 由 `f32::from_bits` 直接构造指数域，`r ∈ {0,1,2,3}` 查四个常量 `1`、`1.189207115`、`1.414213562`、`1.681792831`。结果在 f32 上精确到最后一位。
4. **禁止 FMA 与任何形式的快速数学重排。** 同一输入在任何目标平台上必须给出位精确一致的结果。Rust 默认不启用 fast-math，本决策要求维持该默认，并禁止用 `mul_add` 替换 `a*b+c`。
5. **舍入、饱和与 denormal 策略逐模块记录。** 收窄 f64 → f32 一律用默认的就近偶数舍入；不启用 flush-to-zero。
6. **公开边界暂定 `f32`，但不锁定 C ABI。** `Ac4SceneFrame` 的 PCM 表示在 M5 单独定夺，本 ADR 只约束内部标量路径。

## 理由

- **位精确可复现优先于逼近精度。** 反量化表的位模式由精确整数判据与固定摘要共同冻结；IEEE 754 的四则运算有精确定义，因此查表 + 四则运算的组合在任何符合标准的平台上给出相同比特。多项式逼近或牛顿迭代做不到这一点，且会让"实现是否正确"与"逼近是否够好"纠缠在一起。
- **与参考解码器的比对必然带容差。** 参考解码器的内部数值格式未知，且比对前至少还要补偿一段流时延（测试向量策略 9.4）。具体数值不写进本 ADR——它尚未在可复现的解码路径上复核，届时可能改变；本条依赖的只是「存在需要补偿的量」，不依赖它等于多少。既然目标不是逐比特相同，就没有理由为多一两位精度付出不可复现的代价。
- **f32 存储匹配输出精度，f64 累加消除长加法的噪声累积。** 二者分工明确：存储量减半，而误差只在真正会累积的地方付出双精度代价。
- **构建期生成表已有先例。** Huffman 码本走的就是这条路（规范可追踪性 5.1）；当前实现由 `build.rs` 调度、`build_support/` 持有生成逻辑，基础设施和审计习惯都已就位。区别是本表不涉及受版权保护的输入，因此可以无条件生成。
- **32 KiB 的表在本项目的量级下不显著。** 现有 `ChannelElement` 单个约 60 KiB，且表在 `.rodata` 而非栈上。

## 影响

正面影响：

- 数值路径完全确定；构建机不参与表值选择，回归基线可以按位冻结，不需要为浮点差异设容差窗口。
- 当前目标侧仍为零外部依赖并保持 `no_std`；构建期已按 ADR-0003 引入唯一且锁定版本的 `libm`，用于生成冻结的 IFFT 根表。
- 增益计算精确，误差只来自反量化表本身，来源单一便于定位。

代价：

- 禁用 FMA 会损失一部分吞吐；ADR-0001 第 7 条已确立标量实现是正确性基线，性能优化须走可差分验证的局部内核，届时任何启用 FMA 的内核都必须单独论证并保留标量路径作为对照。
- f32 存储与 f64 累加混用，接口上需要明确每个缓冲的格式，误用不会被类型系统之外的东西挡住。
- 反量化表的生成器要执行 8 192 次精确整数搜索并核对完整位表摘要；这只增加一次构建期工作，不向目标引入代码或依赖。

## 被否决方案

### 全程 f64

省去格式转换，精度充裕。但存储翻倍（21 个上混信号 × 2 048 点 × 8 字节 ≈ 344 KiB），且未来 SIMD 化的吞吐直接减半，而多出的精度对 24 位输出没有可感知的收益。

### 定点（Q 格式）

嵌入式友好，且天然位精确。但 `scaled_spec` 的规范全域动态范围达 `2^81`，单一 Q 格式无法覆盖，必须引入分段缩放或块浮点，把复杂度转移到每个 DSP 模块里；正确性论证的难度远高于本 ADR 试图解决的问题。若未来出现明确的定点目标平台，应作为独立后端而非替换基线。

### 依赖 `libm`

一行依赖即可获得 `powf`/`exp`。运行期取用仍被否决：依赖会进入目标二进制并参与每次解码，而 `|q|^(4/3)` 有整数出口，查表方案的成本更低、结果更可复现。

**构建期取用的否决已被 ADR-0003 推翻。** 本节原称「`libm` 的结果不保证跨版本位一致」——跨版本确实可能变（ADR-0003 因此精确锁版本）。`libm` 的纯 Rust 算法避开宿主 `std` 背后的平台 libm，显著缩小跨平台漂移面；但其源码仍保留必要的目标条件分支，契约不建立在「绝无平台分支」的假设上。精确锁版本配合冻结摘要，保证所有成功构建只接受同一张表，差异平台会闭锁失败。

### 多项式逼近 `x^(4/3)`

省去 32 KiB 表。但需要为精度、分段边界和系数来源各写一套论证，而这些论证无法用规范条款支撑——它们是实现自选的近似，一旦与参考解码器出现偏差，无法区分是逼近误差还是实现错误。

### 表值直接写入版本控制

免去构建期工作。但 8 192 个 f32 字面量既不可读也不可审计，而 `build.rs` 的整数生成规则可以直接审查，并以固定摘要、单调性和端点断言约束完整输出。
