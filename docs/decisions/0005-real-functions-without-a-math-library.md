# ADR-0005：目标侧的实数函数

- 状态：Accepted，补充 [ADR-0002](0002-numeric-format-for-reconstruction.md) 第 3 条
- 日期：2026-08-15

## 背景

ADR-0002 已经记录了这条约束：**`no_std` 下 `core` 不提供超越函数，`sqrt` 起就已不在其中**。当时 `5.1.3` 的反量化用查表绕开了它，`5.5` 的变换常数由 ADR-0003 在构建期用 `libm` 算好冻结成表。两条路子都成立，是因为那些函数只在**有限个已知点**上取值。

`5.7.6.4` 的 HF 生成不再具备这个性质。逐条勘查该节的 640 行正文：

| 需求 | 次数 | 处理 |
|---|---|---|
| `pow(x, 2)` | 8 | 平方，四则运算 |
| `pow(x, k)`，`k = 0…3` | 1 | 整数幂 |
| `pow(-1, n)` | 1 | 符号 |
| `pow(2,-20)`、`pow(10,-12)`、`pow(10,5)` | 4（3 个不同常量） | 编译期常量 |
| **`sqrt`** | **6** | `Pseudocode 90`–`94` 的增益与电平 |
| **`log10`** | **1** | `Pseudocode 85` 的 `10·log10(pow_env + 1)` |
| **`pow(10, ·)`** | **1** | `Pseudocode 85` 的 `10^((mean − slope)/20)` |

15 处 `pow` 里只有一处需要任意实数指数。真正的新需求是三个：`sqrt`、`log2`、`exp2`（后两者承载 `log10` 与 `pow(10, ·)`）。这三个都在运行期对任意实数求值，查表和构建期预计算都用不上。

一并勘查过的替代方案里，只有一条是真出口：**f64 的四则运算在 `no_std` 下完全可用**。规约用位运算精确完成后，剩下的部分可以在 f64 里用级数算到远超 f32 所需的精度。

## 决策

1. **在 `crates/macindecode-ac4-bitstream/src/math.rs` 实现 `sqrt`、`log2`、`exp2`，全部 f64 入出。** 目标侧仍然不链接 `libm`——ADR-0003 第 2 条的边界不变，`libm` 只出现在 `[build-dependencies]`。

2. **算法逐条固定，因为它们决定结果的位。**

   - `decompose(x) → (m, e)`：位运算取指数与尾数，`m ∈ [1, 2)`，无舍入；次正规先乘 `2^54` 抬进正规区再补偿指数。
   - `sqrt`：规约到 `m ∈ [1, 4)` 与偶数指数，初值 `(m+1)/2`，牛顿迭代 `y ← (y + m/y)/2` **固定六步**。初值的相对误差是 `(√m−1)²/(2√m)`，在 `m = 4` 处最大为 1/4；二次收敛给出 `0,25 → 3,1×10⁻² → 4,9×10⁻⁴ → 1,2×10⁻⁷ → 7,2×10⁻¹⁵ → 2,6×10⁻²⁹`，五步已越过 f64 的分辨率。取固定步数而非收敛判据，避免一个可能不终止的循环。
   - `log2`：把 `m` 折到 `[√2/2, √2)`，`t = (m−1)/(m+1)` 满足 `|t| ≤ 0,1716`，用 `ln(m) = 2·Σ t^(2k+1)/(2k+1)`，`k = 0…11`。`t`、Horner 求值与换底用高低两个 f64 保留普通算子丢掉的舍入残差，最后一次舍入；末项量级约 `10⁻²⁰`。
   - `exp2`：拆成 `x = n + f`，`n` 取最近整数，`|f·ln2| ≤ 0,3466`，`e^(f·ln2)` 用 17 项指数级数 Horner 求值，截断误差约 `10⁻²³`；再乘 `2^n`。
   - `sqrt_f32`：全程 f64，只在返回时收窄一次。理由与 ADR-0003 第 5 条用 `libm::sqrt` 而非 `sqrtf` 相同。

3. **不使用 `f64::mul_add`。** 它不在 `core` 中，且在有无 FMA 指令的目标上舍入次数不同——同一份源码会产出不同的位。这与 ADR-0003 用冻结摘要闭锁跨平台确定性是同一个考虑，只是这里没有表可冻结，只能从算子层面排除掉不确定性。全部写成普通乘加。

4. **`2^n` 的构造必须夹住指数，余量单独相乘。** `n` 取最近整数，因此它可以落在 f64 正规指数范围之外而结果仍然可表示：`2^1023,5 ≈ 1,34×10³⁰⁸` 小于 `f64::MAX`，`2^-1074` 也还是个次正规数。直接构造 `2^n` 会在中间步骤溢出或下溢，把可表示的结果算成 `±∞` 或 `0`。

   这一条不是假想：`aspx::dequant` 的 `pan_denominators` 曾在 `2^127,5` 上犯过同一个错误，本模块随后又犯了一次（`exp2(1023,5)`），两次都是**最终值可表示、中间值不可表示**。

5. **判据分三层，缺一不可。**

   - **精确点**：2 的整数次幂上 `log2`/`exp2` 精确（覆盖 `-1074…1023`，含次正规），完全平方数上 `sqrt` 精确。这一层只检验规约路径——2 的幂上级数取值恒为 0，根本不参与求值。
   - **代数律**：`log2(x·y) = log2(x) + log2(y)`、`exp2(a+b) = exp2(a)·exp2(b)`、两者互逆。不依赖任何具体算法，级数系数写错就不成立。两条只在正规数上取，因为次正规的 `x·y` 自身的舍入远大于本模块的误差；判据取**绝对**偏差，`log2` 的结果可以任意接近 0。
   - **独立实现对照**：与 `std` 的同名函数逐点比 ulp，以及源码内嵌的高精度锚点表。

6. **精度以 ulp 记录，不冻结位序列。** 级数实现没有可冻结的表，ADR-0003 那套摘要在这里没有对象。取而代之的锚点是 `math.rs` 里的采样表：单元测试要求实现命中它，`scripts/check_math.py` 用 `Decimal` 以 80 位十进制要求它本身正确。两边都改才能一起漂移。当前实测：

   | 判据 | 结果 |
   |---|---|
   | 与 `std` 的最大偏差 | `sqrt` 1 ulp、`log2` 1 ulp、`exp2` 1 ulp |
   | 次正规区 `exp2` | 0 ulp |
   | `sqrt_f32` 与硬件 `f32::sqrt` | 27 001 个采样点**逐位相同** |
   | 与高精度锚点 | ≤ 1 ulp（52 个值） |
   | 对数律绝对偏差 | `1,14×10⁻¹³`（理论量级 `1,2×10⁻¹³`） |
   | 往返偏差与理论界之比 | 0,403 |

   往返判据的容差取 `|log2(x)|·ln2 + 4` 个 ulp 而不是常数：`log2(x)` 的量级到 1024 时 f64 在那里的分辨率是 `2^-42`，`exp2` 把它放大成约 718 ulp 的相对误差。**即便两个函数都正确舍入，`x = 2^-1022` 附近的往返也回不到 2 ulp 以内**——这是数学必然，写死一个宽松的魔数会同时放过真实的缺陷。

## 理由

三层判据的分工在注入实验里是实打实的，不是修辞。八类缺陷注入全部被捕获：`log2` 级数只留前 3 项、`1/7` 写成 `1/9`、`exp2` 级数减到 4 项、换底除以 `LOG2_E`、`sqrt` 迭代减到 3 步、`decompose` 不处理次正规、`exp2` 不夹指数、`sqrt` 漏掉偶指数调整。

同时另有一组**等价变体**用来证明判据不过紧——换一种同样正确的写法时判据必须保持沉默，否则它锁死的是实现细节而不是行为：`log2` 折叠阈值改用 1,5、`exp2` 两次乘法对调、`sqrt` 初值改成常数 1、`log2` 级数多算两项，四条全部无判据失败。

`exp2` 的两次乘法先后曾被误认为影响精度。实测（可达区间全扫）两种顺序都是 0 ulp：先乘 `2^clamped` 时 `sum < 1` 的中间值虽然会掉进次正规，但最终结果的有效位数更少，丢掉的位本就不参与最终舍入。实现取「先小幅调整、再一次到位」，因为它的中间值恒为正规数，不必依赖这个吸收论证——但注释里不能声称另一种写法是错的。

## 影响

- 目标侧依赖仍为零，`no_std` 目标的依赖图不变。
- `5.7.6.4` 的 HF 生成、`5.7.6.3.5` 之后的所有幅度域运算都有了可用的实数函数。
- `5.1.4` 谱噪声填充此前以「需要任意实数的 log2/pow2」为由推迟（见规范可追踪性 5.17），该理由的这一半现已不成立；剩下的一半——正态随机数发生器——仍然有效，且 `b_snf_data_exists` 在八条流上恒为假，因此推迟的结论不变。
- 精度上界随源码走，任何算法改动都要重跑 `scripts/check_math.py` 与三层单元判据。

## 被否决方案

**目标侧链接 `libm`。** 最省事，但直接推翻 ADR-0003 第 2 条与项目的零依赖边界。`libm` 自身带 `target_arch` 条件分支，ADR-0003 是用冻结摘要闭锁这类漂移的；运行期调用没有摘要可冻结，确定性就只能靠信任。

**用 f32 精度的快速近似（如位技巧 + 少量牛顿步）。** 在音频重建里够用，但把误差分析引入了每一个下游环节：`Pseudocode 85` 的增益要经过多项式拟合与 dB 往返，误差会被指数放大。f64 级数的成本只有几十次乘加，没有理由省。

**构建期生成分段多项式系数表。** 是 ADR-0003 的自然延伸，但对这三个函数没有收益：规约之后的级数只有十几项，查表反而要处理分段边界与区间选择，代码更多、可审计性更差。
