# ADR-0004：混合基 Stockham IFFT 标量基线

- 状态：Accepted
- 日期：2026-08-13
- 关系：落实 [ADR-0003](0003-trigonometric-tables-for-the-transform.md) 第 7 条；数值格式继续服从 [ADR-0002](0002-numeric-format-for-reconstruction.md)

## 背景

`TS103190-1:v1.4.1:Pseudocode 61` 定义长度 `M = N / 2` 的复数 IFFT：指数取正号，IFFT 内不归一化，`Pseudocode 62` 才在后旋转时除以 `N`。十五档 `N` 对应的 `M` 为 `48…1024`，且都只含质因子 2、3、5：`2^a`、`3×2^a` 或 `15×2^a`。

实现还必须满足 `no_std`、稳定解码期间零分配、禁用 FMA，以及可由规范定义式独立差分验证。

## 决策

1. **标量基线采用 out-of-place mixed-radix Stockham autosort。** 每级在输入缓冲与一个固定 scratch 间交替，结果自然有序，不另做 digit/bit reversal。
2. **只使用 radix-4、2、3、5，并冻结为 power-first 顺序：先尽可能取 4，再取余下的 2、3、5。** 十五档计划由测试逐项锁定，例如 `M=960 → [4,4,4,3,5]`、`M=120 → [4,2,3,5]`、`M=48 → [4,4,3]`。这条规则比逐长度手写计划更容易审计。
3. **工作值与蝶形累加使用复数 f64，且不使用 `mul_add`。** 输入 f32 提升后参与计算，最终按 ADR-0002 收窄。IFFT 本身保持正号、无归一化；不能把 `1/M` 或 `1/N` 藏进蝶形。
4. **调用方提供一个 `[Complex64; 1024]` scratch，共 16 KiB。** 算法不分配，不递归；最后一级落在哪个缓冲由级数奇偶决定，后旋转直接读取该缓冲，避免一次全长复制。
5. **IFFT 根表使用完整、直接可审计的布局。** 按 `TRANSFORM_LENGTHS_48` 顺序，对每个 `N` 令 `M=N/2`，按 `e=0…M−1` 依次存 `cos(2πe/M)`、`sin(2πe/M)` 的 f32 位模式。共 10 664 个 f32、42 656 字节，SHA-256 为 `76261b2212836ee22fbf162ea6a2bcc35233bdd54dec8fa60cb15b51a452ef6b`。生成与审计只在第一象限求值，其余项由换位、变号和共轭派生；轴点精确写 `±1/+0.0`。运行期不求三角函数。
6. **保留规范直写的 `O(M²)` DFT 作为测试 oracle。** 它不进入生产路径。任何蝶形专化或 SIMD 内核都必须在十五档长度上与该 oracle 差分，并保留标量 Stockham 基线。

## 验证证据

生产内核与测试位于 `asf/imdct/ifft.rs`，参与默认 `no_std` 构建但保持 crate 内可见，避免提前冻结 DSP API。算法层先以 f64 根在全部十五档长度上把两个因子顺序与定义式紧容差差分；数值层直接调用生产函数，并单独约束 f32 根表的量化误差。另有独立用例锁定非法长度不改写输入、正号、自然顺序、无归一化、根表轴点/共轭/象限换位结构和 16 KiB 固定 scratch。

根表的**具体值**不由单元测试校验，只校验表内的派生关系。若改由宿主 `cos`/`sin` 复算并逐位比对，测试就绑定了宿主实现：构建按 `libm` 生成且摘要一致，而两者只要有一项收窄后不同，失败信息就会指向「量化不匹配」，掩盖真实原因（本机实测这批角度上 f64 有 116/2 636 项位模式不同，收窄 f32 后为 0 项，但那是本机结论而非契约）。具体值由 ADR-0003 的冻结摘要与 `scripts/check_transform_tables.py` 的高精度审计锚定。这条分工有实测支撑：把第一象限到第二象限的换位写反，构建期的轴点、单位圆、共轭与象限符号检查**全部放过**——换位后模长仍为 1、共轭派生仍成立、轴点又是单独写入的——只有摘要与该派生用例抓得住。

固定复数 f32 探针遍历十五档长度时，生产根表相对 f64 定义式的整体相对 RMS 误差为 `4.12×10⁻⁸`（约 −147.7 dB），最坏归一误差为 `1.47×10⁻⁶`，后者出现在接近抵消的输出点。回归预算分别设为 `1×10⁻⁷` 与 `4×10⁻⁶`；根表另由 100 位十进制审计逐项确认正确舍入并核对完整摘要。

release 微基准每轮对全部长度各执行 200 次。两次独立的五轮测量中，首次 power-first 与 odd-first 的中位数为 10.725 ms 与 10.702 ms（odd-first 快 0.22%），复跑则为 10.645 ms 与 10.778 ms（power-first 快 1.24%）；领先方向反转，不足以形成性能结论。因此不以噪声选序，而采用规则更简单的 power-first；微基准保留为 ignored test，不进入 CI 门禁。

## 理由与影响

Stockham 用一个可预测的小 scratch 换掉了原地 Cooley–Tukey 的混合基重排与复杂别名关系，符合工作区复用模型。所有长度都能由 2/3/5 分解，Bluestein 的额外卷积、补零和工作区没有收益；纯 radix-2/split-radix 又无法覆盖 3、5 因子。

完整根表比按级压缩多占少量只读数据，但索引与审计规则固定，不把表布局绑定到未来的蝶形专化。加入后，三张变换表合计约 125 KiB，加 32 KiB 反量化表约 157 KiB `.rodata`。

## 被否决方案

- **直接 DFT 作为生产实现**：最清晰，但最大长度从 `O(M log M)` 退化到 `O(M²)`；只适合作 oracle。
- **原地 mixed-radix Cooley–Tukey**：可省 16 KiB，却需要混合基重排；当前内存收益不足以抵消验证复杂度。
- **Bluestein**：本项目没有质数或其他难分解长度，卷积计划纯属额外成本。
- **外部 FFT crate**：常见 planner、堆分配、`std`/SIMD 自动选择与 FMA 策略不符合确定性标量基线；未来可作为非基线优化重新评估。
