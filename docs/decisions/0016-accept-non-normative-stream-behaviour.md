# ADR-0016：接受规范之外的现实行为

- 状态：Accepted
- 日期：2026-09-10
- 关系：补充 [ADR-0001](0001-language-and-project-boundary.md) 的项目边界；为
  [规范可追踪性](../SPEC_TRACEABILITY.md)第 8 节提供决策依据；不改变任何数值决策，也不放宽
  支持矩阵中任何未覆盖路径的 fail-closed 行为

## 背景

README 的支持矩阵与 CLAUDE.md 都写着同一条原则：**未覆盖路径一律 fail-closed，不静默降级。**
`b_static_dmx = 1`、channel-based、direct-object/mixed、SIMPLE、1 024 及以下短帧、活动
companding、FIC/TIC 交织与活动 core DE 全部显式拒绝。

但实现里已经存在两类**被接受**的非规范数据：

- 12 条自产 A-JOC 基线向量的首个 independent presentation payload，在 P2 `6.2.2.3` 末尾的
  `byte_align()` 之后多出一个完整字节——7 条是 `0x00`、5 条是 `0x80`。
- 2026-09-08 播放一份**非自产**样本时出现第三个取值 `0xd8`：6009 个 AU 中 252 个
  independent object/A-JOC 帧全部携带它，其余 5757 帧没有尾部。当时仅限 `{0x00, 0x80}` 的
  兼容入口会在 AU 0 拒绝整个播放会话，而该文件其余部分完全正常。

这是对 fail-closed 原则的明文例外，此前没有任何 ADR 记录它——只有 bitstream 里的一个常量和
测试向量策略 9.2m 的几段散文。第 8 节已经把条目表格化，但**表存的是条目，不是决策**：为什么
可以有这个例外、它的边界在哪、凭什么说它不侵蚀原则，这些没有落点。

`0xd8` 的来源也说明这类条目会持续到来：它由播放真实文件发现，而自产编码链至今不产生它。

## 决策

1. **确认例外，并划死它的范围。** fail-closed 仍是默认行为。例外只适用于「规范在该位置不
   产生任何数据，而真实工具链稳定地写出它」的情形，且必须先证明规范语法**恰好耗尽**。
2. **例外与 fail-closed 不冲突，因为两者的对象不同。** fail-closed 守的是「不把未验证路径
   当已支持」——未实现的数值路径、没有真实样本的分支，那是**我们没能力做的事**，放行等于
   谎报。本例外处理的是**规范没有描述的现实**：此时规范语法已经完整解出，多出来的是与语法
   无关的字节。误拒它不产生任何安全收益，只会让整份文件不可播。
3. **严格路径永不改变。** 兼容只能是独立入口：
   `Ac4PresentationSubstream::parse_with_drc_state_compat` 与严格入口 `parse_with_drc_state`
   并存于 `macindecode-ac4-bitstream`，由调用方（`macindecode-ac4-scene::session`、
   `macindecode-ac4-metadata::presentation`）显式选择。这样「我们对规范的理解」与「我们对
   现实的让步」在代码里始终分得开，任何一天想退回纯规范行为都只是不调用那个入口。
4. **登记门槛三条，缺一不可**（完整表述见第 8 节，本 ADR 不复制）：规范语法恰好耗尽；有真实
   样本与命中统计；检索过约束该字段的条款，而不只是检索过该符号。
5. **单一声明点。** 条目登记在规范可追踪性第 8 节的表中，实现侧的常量注释指向该节。本 ADR
   只存决策与边界，不存条目——两处存同一份数据必然漂移。
6. **不外推。** 接受一个字节不等于接受该位置的任意字节，也不等于接受其他位置的类似现象。
   每一条独立论证、独立登记、独立设门槛。
7. **保留降级路径。** 找到等价条款后，条目从第 8 节移入第 6 节或第 7 节，或直接消解。登记时
   记录检索范围就是为了让这一步可复核。

## 理由

- **最大的风险是把一处真实的漏读粉饰成「编码器写了个怪字节」。** 因此「规范语法恰好耗尽」
  是登记的**前置条件**而不是事后说明。`0xd8` 这次能确认，靠的是规范语法在完整 DRC
  configuration 与 `loud_corr()` 之后、bit offset 128 处结束且 `alignment_bits == 0`，尾字节
  落在 16 字节前缀之后；构造测试另外遍历其余 253 个字节验证拒绝与状态回滚。门槛松一点，这条
  证据就不存在了。
- **一条被接受的例外若不记录，下一个人只能从常量反推**，且无从判断新出现的现象是否适用同一
  门槛。CLAUDE.md 已经记过同构的教训：没有结论时下一个人还会去查，有了假结论他就绕开了。
  一个不写下来的例外，效果等同于一条假结论。
- **外部参考解码器裁决不了这一类。** 它对这些字节的处理同样是产品行为而非规范，与它一致
  既不能证明读法正确，也不能证明该数据合法。所以本节不适用第 7 节「接上 oracle 后按图索骥」
  的方法，只能靠更多真实样本或向 ETSI 确认。

## 影响

正面影响：

- fail-closed 这条原则重新变得可信：它现在有明确的适用范围和一个有边界的例外，而不是一句
  与实现不符的绝对表述。
- 兼容集合的每次扩充都留下可复核的证据链，而不是又一个 magic number。

代价：

- 每次扩充都要过三条门槛并登记，成本略升。
- 第 8 节会随发行持续增长。条目多到一定程度时，需要评估是否把兼容判定收敛成独立模块，而不是
  继续在各解析入口分散判断。

## 被否决方案

### 严格 fail-closed，拒绝任何非规范字节

把「规范纯洁性」置于「文件能不能用」之上。`0xd8` 那次的实际后果是在 AU 0 拒绝整个播放会话，
而该文件其余 6009 帧全部正常解析、6008 帧完成 Full 重建。这个拒绝不产生任何安全收益：规范
语法已经完整解出，被拒的是它之后的无关字节。

### 宽松跳过任意尾随字节

会把真实的漏读全部吞掉——少读一个字段和多出一个字节，在这种做法下无法区分。`0xd8` 之所以能
被确认为前者之外的情形，正是因为门槛要求先证明前缀耗尽。

### 只在 Scene 层容错，bitstream 完全不知情

兼容判定需要「严格路径还剩多少比特、对齐状态如何」这类只有 parser 掌握的信息。放到上层等于
重新实现一遍解析，并且会产生第二个关于「规范语法在哪里结束」的真相源。
