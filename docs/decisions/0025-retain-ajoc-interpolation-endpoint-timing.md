# ADR-0025：保留 A-JOC 插值的起点端点时序

日期：2026-11-08。状态：已采用，限定为本仓库默认日程的工程裁决；官方符合性问题仍开放。

## 决策

保留当前生产日程。设 `s = ajoc_start_pos`、`N = ajoc_ramp_len_minus1 + 1`：

- 在时隙 `s` 先求出旧 ramp 在该位置的值 `A`，以它安装新目标 `B`。
- 新 ramp 第一增量在 `s + 1`；未被后续事件打断时，在 `s + N` 到达 `B`。
- dry、wet、pre 共用一次时隙推进；无新数据点的帧继续未完成 ramp。
- 长度仍为恰好 `N` 次增量，终点仍钉到 target。计数、浮点运算和终点策略不随这次
  时序裁决一起改变。

这次把“是否立即切换生产默认”收口为**保持**，没有把未解决的外部符合性声明改成通过。
不新增兼容开关，不改生产运算、Scene 时间戳、PCM 基线或规范版本。

`5.7.3.6.1` 的 P18 把这个返回值直接用于同一 `ts` 的矩阵乘法，之后才更新 ramp 控制。

`6.3.6.4.2` 将 `start_pos` 定义为参与插值的第一个 QMF 时隙，`6.3.6.4.3` 给出长度。

## 可检验的端点契约

对未中断的 ramp，用绝对 QMF 时隙 `t` 表示理想曲线：

```text
c(t) = A + (B - A) × clamp(t - s, 0, N) / N
```

它在 `s` 为 `A`，在 `s + N` 为 `B`。`N` 度量的是相邻端点之间的时隙间隔；列出
两端会得到 `N + 1` 个取样位置，不代表执行 `N + 1` 次增量。实际实现仍使用原有 f32
累加，公式只规定时序及端点，不要求中间舍入与闭式求值逐位相同。

若新事件在 `u` 中断旧 ramp，新曲线的起点取旧曲线的 `c(u)`，不是 `c(u - 1)`。
例如从 0 到 4、长度 4、起点 0 的 ramp，在时隙 2 改为目标 10、长度 2，结果为
`[0, 1, 2, 6, 10]`。若起点 31、长度 1，则时隙 31 保持起点值，下一帧时隙 0 到目标。

反过来，在固定算术与同一初始状态下，当时隙第一步的候选可以看成另一种系数取样
日程。两种日程都能构造连续分段曲线，单凭连续性或端点覆盖无法证明哪一种符合作者
的物理时间意图。系数相差一个时隙也不等于整段 PCM 可平移 64 样本：矩阵输入仍使用
当前时隙的音频，wet 还有自己的递归历史。

## 验证与影响

新增 `interp::timing_contract_tests`，直接用绝对时隙的分段直线计算预期，不复制
production 的增量更新循环。采用二进制有理斜率，避免把舍入差异混进时序检查：

- 5,504 条链：24／30／32 时隙帧的全部合法起点 × 全部 1–64 长度；执行完整尾部，
  包括 64 槽无中断终点及之后保持。
- 8,064 条链：从首／末时隙出发，在 64 槽 ramp 的每个内部端点中断，遍历全部新长度；
  覆盖帧内两点、跨帧、混合帧长，逐位检查 dry／wet／pre 及共享游标。

这些测试证明代码符合本决策，**不能把工程选择升级成官方规范 oracle**。64 槽完整
终点是自有构造覆盖，未扩大原生参考覆盖。历史调查和失败证据保持原样。

执行命令及实际结果记录在同一[复核记录](../experiments/ajoc_interpolation_timing_decision.json)。
本次没有生产运算变化，无需重冻音频基线；历史完整流通过数不冒充本次重跑结果。
