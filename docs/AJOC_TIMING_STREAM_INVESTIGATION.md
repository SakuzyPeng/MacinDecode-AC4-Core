# A-JOC 受控码流：非零起点、非整帧 ramp 与 OAMD 配对

日期：2026-10-23；起点 `a1c1f49`。本轮只增加测试观察、构造工具、检查器与证据，
生产 DSP、公开接口、CLI、默认选项及三层 PCM 基线不变。
机器结果见 [`ajoc_timing_stream_comparison.json`](experiments/ajoc_timing_stream_comparison.json)，
固定构造清单见 [`ajoc_timing_stream_cases.json`](experiments/ajoc_timing_stream_cases.json)。

## 结论

38 个固定配置都完成了完整本地解码、无 DSP 观察器的参考调用及复跑、两个独立进程的
参考捕获。本地保持现有 P17/P18 判读；参考在实际 `start_pos` 时隙安装并执行第一步，
以 f64 倒数收窄到 f32 后相乘形成 delta，执行 N 次增量后停止，不额外钉到目标。
非零起点、非 32 长度、跨帧延续和被下一目标打断的行为，均由独立连续事件模型逐位预测。

没有发现要求修改本地生产算法的独立反例。受控码流扩大的是**参考运行时的构造覆盖**，
不是编码器原生覆盖，也不单独裁决正文语义与 P17/P18 的冲突。

OAMD 配对还暴露了一个更具体的时间锚点缺口：原生 OAMDI getter 返回的偏移字段与旧
scene 导出桥接的坐标，尚没有非零偏移的采样单位凭证。不能用这个桥接坐标来判定本地
插值错了一时隙，也不能未经核对就把它乘 32 当成已修复。

## 等长构造与来源保护

A-JOC 字段位置由实际有界解析器在 `cfg(test)` 下记录，位置相对原始完整裸流；group
OAMD 在测试驱动中先由公共解析器定界，再逐字段读取并核对解析结果。没有通过全文件
搜索相似比特串来定位字段，也没有给生产 API 增加诊断开关。

只修改两个 5／6 位 A-JOC 字段，或现有 OAMD 的 6 位 block offset 和 4 位 ramp 表索引。
数据点数、sample-offset 编码路径、矩阵参数、对象属性、ASF/A-SPX 数据和所有帧长度保持。
每份凭证记录母流／变体 SHA-256、raw AU、字段绝对位置、宽度、旧值、新值及载荷边界；
独立验证器拒绝白名单之外的比特变化。生成器支持 CRC-16/0x8005 的重算和校验，当前两份
母流实际为不带 CRC 的 AC40；CRC 路径由自有包络和已知答案验证。

| 母流与目标 | 固定配置 |
| --- | --- |
| 音乐 raw AU 99 → 消费 AU 100 | 起点 0／1／15／31 × ramp 1／2／31／32／33／64，共 24 组，含原值对照 |
| 同一音乐 raw AU 32 → 消费 AU 33 | 起点 1／31 × ramp 1／33／64，共 6 组 |
| 音乐 AU 99 的 OAMD 配对 | 对 (1,1)、(15,2)、(31,32) 分别只改 OAMD、同时修改两者，共 6 组 |
| 强纯音 raw AU 7 → 消费 AU 8 | (1,2)、(31,64)，共 2 组稳定矩阵控制 |

OAMD 配对使用 `block_offset_factor=2×start`、`ramp_duration=64×ramp`，沿用表编码。
每帧仍只有一个数据点；64 槽案例只能证明跨帧与中断，不能记作其无中断终点已覆盖。
本轮也没有新增零／双数据点、其它帧长、其它拓扑或其它参考版本的原生覆盖。

## 本地完整链与参考实际消费者

38 份流合计 **14,686 AU**，全部连续运行到 EOF。Core PCM、完整 A-SPX QMF 和另外导出的
A-SPX PCM 均与各自母流逐位一致；路由前后检查及选定窗口的实际 X 保持不变。所有帧的
矩阵原始符号、量化控制及对象属性保持，所有选定窗口的矩阵目标逐位保持。OAMD 时间
按原始字段独立换算，控制 FIFO 仍把 raw AU n 交给消费 AU n+1。

参考为同一已锁定 DRP 4.3.0.19350 arm64。每份变体使用自己的参考 PCM 摘要，不要求
改过矩阵日程的流仍等于原流输出。每个配置有四份有效完整调用：无观察器基准、无观察器
确认，以及两个独立进程的三帧观察；合计 152 份有效调用。捕获必须保持该变体的完整
PCM 摘要、全部 AU 成功返回、参数设置成功和有限样本。

额外核对改动 raw AU 之前的 PCM 前缀与原流参考逐位相同。此项排除了一个虽然完整、有限，
但在改动发生前已出现异常数值的参考基准；随后用新的完整基准、确认和捕获重新建立证据。
总计 33 次未通过门禁的尝试保留了记录，包含进程异常、不完整运行和不一致输出。它们
没有被解释成码流不受支持、没有进入数值比较，也没有因局部捕获成功而放行。

每次观察相邻三个消费 AU，实际保存使用中的 dry/wet、pre、目标、delta、游标、X/Y/Z
和输出缓冲区身份。非零起点下，目标准备前快照发生在命中时隙，**不能当作该帧首状态**；
检查器从前一未改帧的真实初态开始连续推进，再在每个目标安装前核对完整状态。

共 114 个窗口、3,648 个时隙；按既有频带映射展开的 **62,337,024 个系数值**以及 delta
和游标逐位符合参考事件模型，第二个进程的全部规范化文件另行逐字节重复核对。对象输出
乘法只比较参考有效子带 0–47；最大绝对差约 7.46e−9，满足沿用的运算量前向误差界。
没有把参考较高地址的工作区当成有效 64 带输出。

## 时序、舍入与终点分开核对

| 项目 | 当前本地判读 | 已测参考消费者 |
| --- | --- | --- |
| 命中起点 | 先推进旧 ramp，再安装新增量 | 安装新增量并立即执行第一步 |
| delta | f32 差值除以 f32 长度 | f32 差值乘以收窄后的倒数 |
| 次数 | 新 ramp 恰好 N 次 | 新 ramp 恰好 N 次 |
| 终点 | 第 N 次钉到 target | 保留重复加法的最后值，随后停止 |
| 下一数据点 | 按当前本地顺序打断旧 ramp | 用当时 current 安装新 ramp，无须先完成旧 ramp |

31／33 等非二次幂长度使除法与倒数乘法可以独立区分：本批安装点有 30,554 个系数分量
的两个候选 delta 位模式不同。参考实际 delta 与由调用路径预先确定的倒数乘法模型吻合，
没有搜索浮点常量或时移。

114 个窗口中，94 个能观察到该帧新目标的完整 N 次增量，其中 89 个仍有至少一个系数
与 target 的位模式不同；最大数值尾差约 3.82e−6。这支持“停止而不钉住”的运行时观察，
不证明本地钉住目标的数值策略错误。未在窗口内完成的 ramp 单独列为中断／延续覆盖。

这里比较的是实际消费系数，不是把整段对象 PCM 平移 64 样本。第一步、delta 舍入和
终点策略是不同变量；新的检查器不再把一般情况简化成“本地下一时隙等于参考”。

## OAMD 配对与导出桥接的单位缺口

三个配对组均得到以下结果：仅改 OAMD 时，参考三帧的矩阵、输入输出以及整段对象 PCM
与原值对照逐位相同；同时修改两者时，这些结果与仅修改 A-JOC 的对应组逐位相同。
本地亦通过相同的音频不变检查。因此在这些输入上，OAMD timing 不会暗中重调矩阵 ramp。

变化确实进入参考元数据出口。独立解析参考 `get_oamd` 的完整返回序列，再调用原生
OAMDI getter，只有第 100 次返回的 timing 字段变化，恰对应 raw AU 99 的修改；对象描述、
位置等记录保持。两个无观察器进程和两个观察进程的 OAMD／scene 导出逐字节相同。

| AC-4 block offset factor | AC-4 独立定义的偏移（samples） | 原生 getter 对应字段 | 旧 scene 桥接坐标的变化 | 原生 ramp 字段 |
| ---: | ---: | ---: | ---: | ---: |
| 2 | 64 | 2 | 2 | 64 |
| 30 | 960 | 30 | 30 | 128 |
| 62 | 1,984 | 62 | 62 | 2,048 |

旧桥接把 getter 字段直接加到名为 sample 的坐标中；原先全为零的素材不能验证这个单位。
本轮保留原始字段和旧桥接坐标，把它们标成 observation，不标成已确认的绝对采样时间。
这里没有证明字段应乘 32，也没有证明参考渲染器错误；实际 metadata 消费者如何解释
该字段尚未核对。A-JOC 与 OAMD 的绝对时间裁决因此仍开放，下一步应先补这一边界。

## 门禁、资源与复现

四类实际生产故障注入全部被捕获：命中时隙提前推进、错误 ramp 长度、跨帧清除游标、
使用旧 OAMD 来源。等价游标比较改写和恢复后的完整流通过；实验改动均已恢复。
新增 16 项无媒体测试加入 CI，覆盖字段定位、白名单、CRC、截断、来源、时钟、中断、
终点与旧桥接坐标。相关 Python 套件共 173 项通过，默认／audio-decode／spec-tables
分别 516／1,331／107 项通过。三套 Clippy、两套 no_std、格式、分层、规范表／来源、
数学／变换常量及工作流检查均通过。

重新构建的 release 验证产物通过原有三层 36 条 PCM 基线；三份完整原始对象流共
25,460,736 个样本保持前轮正式导出。正式二进制恢复原摘要，基线文件没有改写。
所有大文件留在核验 UUID 的 cache 卷，复用原构建目录；有效参考重复 PCM 在摘要验证后
删除，本地相同完整输出用硬链接去重，另节省约 4.05 GB。

```bash
# 先使用已有完整流驱动提取母流；指定新目录，并保留本轮所需窗口。
MACINAC4_AJOC_FIELDS=1 MACINAC4_AJOC_MATRIX=1 \
MACINAC4_AJOC_INPUT_STREAM=/absolute/path/input.ac4 \
MACINAC4_AJOC_INPUT_OUTPUT=/absolute/path/new-seed \
MACINAC4_AJOC_INPUT_AUS=32,33,34,99,100,101 \
  cargo test -p macindecode-ac4-decode --features audio-decode \
  capture_ajoc_input_boundary -- --ignored
# manifest 的 seeds 保存 tone/music 的 input、input_sha256、directory；maps 保存路径与摘要。
python3 scripts/check_ajoc_timing_stream.py /absolute/path/manifest.json \
  --prepare /absolute/path/new-experiment
# 对生成的 cases 用同一驱动完整解码，随后检查；参考适配器和原始 SDK 数据保持本地。
python3 scripts/check_ajoc_timing_stream.py /absolute/path/new-experiment/manifest.json \
  --reference /absolute/path/reference_manifest.json --output /absolute/path/comparison.json
python3 -m unittest scripts/test_check_ajoc_timing_stream.py
```

公共生成器已逐字节复现全部 38 份变体及改写凭证。参考扩展使用独立的连续事件检查入口，
原 `start=0、ramp=32` 历史实验协议保持可复验，不通过放宽旧协议来冒充新覆盖。

2026-10-23 后续 [OAMD 消费边界验证](OAMD_CONSUMER_TIMING_INVESTIGATION.md)已确认
原生 getter 保留 factor，OAR 实际乘 32；旧 scene 桥接漏乘的失败复现单独保留。
本报告记录的当时单位缺口由此补齐，A-JOC 绝对同步与端点解释仍保持开放。
