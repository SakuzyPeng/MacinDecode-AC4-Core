## 结论

**历史上的 31 样本偏移已有实际消费者解释。** 已测参考在终端 QMF 合成之后，按
32 样本粒度进行输出格式转换，并保留 31 个尚未转换的输入样本。下一批输出先使用这段
历史，再使用新输入；转换器直接写入解码 API 返回缓冲。实际状态、输入、目的地址和
序列化字节共同验证了这条交接，不再需要从末端 PCM 搜索 31。

**352 是另一条时间参数。** 本地表 188 的 PCM 对齐延迟与参考 OAMD API offset 均为
352，但来源和用途分别记录，不能把它们互相抵消或重复计入。Scene codec 坐标与 OAR
输入 PCM 坐标相差 352；把后者映射回格式转换前，数值差为 `352−31=321`。这只是已测
缓冲坐标与调度位置的差，不能推出生产 Scene 应平移 321，也不能证明两个实现的
“同一物理音频时刻”已经完全对齐。

当前证据仍不足以唯一裁决 A-JOC 第一增量时刻。固定算术策略的两个候选在自有输入上
可以区分；实际参考的命中时隙第一步、倒数乘法及不钉终点也可独立重放。但 QMF 值具有
有限支持区间，不能直接等同于 OAMD 的瞬时事件或 OAR 的块中点查询。P2 字段语义与
P17/P18 调用顺序的解释冲突继续保留。本轮没有形成新的独立生产错误反例或 DSP 修复建议。

## 坐标定义与独立模型

全部时间采用有符号整数，每个 48 kHz 样本为 6 ticks；拒绝溢出、浮点下标和无法整除的
PCM 下标转换。各缓冲的第一个元素有自己的声明原点，不把内存 stride 当作延迟。

对已验证的居中采样网格，参考内部宽度为 `M` 时：

```text
t48(i,M) = (i+1/2) × 64/M − 1/2
tick(i,M) = (384i+192)/M − 3

M=64: 6i       M=48: 8i+1       M=8: 48i+21
352 samples = 2112 ticks = 264 个 M=48 样本 = 44 个 M=8 样本
```

这保留了 48／8 宽度分别为 1/6／7/2 个全带样本的原点，未四舍五入。
复用并重新运行[IMDCT 专项](ASF_IMDCT_BOUNDARY_INVESTIGATION.md)的独立模型和既有
82 个原生变换块；1,080 个旧 Core 声道帧与当前捕获逐位一致，块几何及来源相同。
这是旧原生覆盖的复核，不计作新参考 IMDCT 捕获。

IMDCT 混合窗口按 `TS103190-1:v1.4.1:5.5.3` 的块中心推导读写时钟：

```text
centre_next = centre + (N_previous+N_current)/2
composition_read = centre − (N_full+N_current)/2
new_history_write = [(N_full−N_current)/2, (N_full+N_current)/2)
```

22 块序列含长块、1024 块、16 个 128 短块及返回长块；总输出 12,288 个样本。
源信号由独立固定种子生成，变换谱、实际窗口和输出另行交给 Python 直接模型重建。
实际完整流新增 7,350 个 IMDCT 块的写入偏移、前块长度和返回指针记录，逐帧验证读位置
连续且铺满本帧；没有为观察增加跨 crate 接口。

PCM→QMF 沿用[独立 640 抽头 FIR](QMF_PHASE_CHAIN_INVESTIGATION.md)，不读取生产调制表。
在本地 ASF PCM 的读出坐标中，低带／LFE 消费时隙 `t` 的输入依赖区间为：

```text
[64(t−6)+63−d_pcm−639, 64(t−6)+63−d_pcm]
```

终端时隙 `t` 的合成支持区间则为 `[64t,64t+639]`，端点均包含。
`TS103190-1:v1.4.1:5.6`／表 188 的 `d_pcm`、一帧控制 FIFO、`5.7.1` 的六个 A-SPX
时隙、分析／合成的支持区间、居中采样网格和 API 标签分别入账。上述低带公式不声称
包含高频生成或去相关 IIR 的全部依赖；它们仍由完整流从起点推进。

## 终端合成到 API 的实际交接

本地测试在生产终端合成调用后记录 QMF、PCM、对象来源和 PCM 指针，再与公共解码返回
视图核对地址及所有位模式。所有 592 AU、12,432 个通道帧通过；导出逐样本保持相同。
12 个窗口的 252 个通道使用实际连续的前 10 时隙有限 FIR 历史，独立重建 516,096 个
终端样本。这个有限历史只用于有限 QMF 合成，不代替上游 IIR 的递归历史。

参考的终端调用与最初假设不同：每批只有四个 QMF 时隙，产出 256 PCM 样本，并复用
scratch。实际单槽写入字节偏移为 `0,256,512,768`，一帧重复八次；不能将 scratch 的首
地址当作连续 2,048 样本平面。观察器逐次收集真正的输出，再核对格式转换器目的地址
等于 API 对应平面的 `group×256` 样本位置，最后与完整 raw PCM 逐字节对照。

格式转换的固定粒度和保留规则经过本地分析与运行时数据核对。

1. 当前配置以 32 样本为转换单位，连续观察时 `carry=31`。
2. 一批 256 个输出由旧 31 个输入与当前前 225 个输入组成；当前末 31 个输入留给下一批。
3. 本批等起止增益路径执行 `clip(x, −limit, limit) × (output_gain×256)`。
   观察值为 `limit=0.25`、`output_gain=1/64`，有效增益为 4；这些来自状态和运算定义，
   不从输出残差拟合。被测窗口没有实际触发限幅，边界由自有模型测试覆盖。
4. 所有可观察 AU 的末 31 个合成样本与保留状态逐位相同；下一 AU 的初始历史再次逐位
   验证。最后返回和序列化没有另外的样本平移。

转换器 setter 前的快照属于上一批设置。bed 的 AU 2 首快照仍保留启动帧 10 路设置，
本帧真正消费的快照已为 21 路。门禁按调用顺序检查消费状态，首快照仍保留作重复性证据；
这次检查器错误和发现过程单独存档，没有更改 PCM 预期或放宽浮点界。

参考从完整起点解码，首 AU 返回后才安装终端原语观察器。首 AU 的完整 API 输出受基准
摘要门禁约束，但它的原语内部调用未观察；不能把首帧初始化或任意格式配置都列为已验证。
真实 EOF 不冲刷最后保留的 31 个输入，也没有人为追加 IIR 预热或尾帧。

## 元数据与音频共同账本

继续使用已修复单位的私有桥接。对 16 配置逐项重验原始字段改写凭证、Scene 事件、
OAMD payload 身份及新导出事件；新捕获与旧 OAR 重放的 PCM、payload 摘要完全相同，
因此复用原先从零状态完成的双进程 OAR 消费记录，并重新执行内部解析／入队／查询检查。
复用的 4,474 次查询不计作新 OAR 捕获。

完整共同账本有 `16×399=6,384` 条 AU 事件，首个预热 AU 单独排除；每条保留 raw 来源、
消费者、对象数量、sample offset、factor、API offset、ramp 和各坐标。实际逐对象 Scene
事件仍为 134,064 条。本批 `F=2048`，raw AU 99 的源起点为 200704：

| 具名坐标 | 事件采样位置 |
| --- | --- |
| P2 `5.9.2` 原始字段 | `200704 + sample_offset + 32×factor` |
| 本地 Scene codec | `202752 + sample_offset + 32×factor` |
| 参考 OAR 输入 PCM | `203104 + sample_offset + 32×factor` |
| 参考格式转换前的对应缓冲下标 | `203073 + sample_offset + 32×factor` |

API offset 352 只在 OAR 输入坐标映射中计一次。每个实际 OAR 查询位置及其剩余 ramp
仍从消费者记录核对：32 样本块在 `16,48,…,2032` 查询，不取整到 64 样本边界。
公开 JSONL 摘录包括 16 个目标事件；完整事件、查询及输入来源在本地实验目录。

上述四行把来源与缓冲下标连接起来，但还没有把一个带 640 抽头支持区间的 QMF 数值
唯一解释成哪个瞬时 OAMD 标签。不能利用末端 PCM 分数在这些原点之间选一个补偿量。

## 插值候选、尾部及封装

先用固定 dry 路由、wet 关闭的全块内脉冲链检查传递，再运行 108 条 dry 时序链。
时序链覆盖 24／30／32 时隙、首／中／末起点、ramp 1／2／31／32／33／64、跨帧、无新点
和中断。每条包含五帧信号和两帧明确标注的人工零尾部，合计 21,672 时隙。
脉冲链另有全部 64 块内位置的 512 个路由／延迟配置，以及两条 IMDCT→QMF 组合链；
均从零状态开始，覆盖完整有限滤波尾部，并验证不同处理分段等价。

两个时序候选固定输入 X、时间原点、除法／逐步 f32 加法及终点钉住策略，只改变安装与
第一增量的先后顺序。108 条链均有非零信号差异；将差异直接通过独立合成 FIR，输出
严格落在相应支持区间内。这证明判据能分辨候选，不表示其中之一由 PCM 相似度胜出。

实际参考的浮点策略另用前轮 38 配置、114 窗口的完整已验证捕获重放：实际 delta 符合
倒数乘法，首步和跨帧游标符合其事件模型，终点保留重复加法的结果。该重放不与“只改变
时序”的对照混合；仍只核对先前已确认有效的前 48 参考输出子带。没有扩大原生编码路径，
也不把 64 槽 ramp 的中断覆盖说成完整无中断终点覆盖。

已有 axes MP4/raw 配对的 143 个 AU payload 逐位相同。实际 CLI batch 路径验证：
21 路 MP4 PCM 等于 raw 的 `[2048,290048)`，长度 288,000；3,003 条元数据事件保持
身份、顺序和 ramp，只平移 −2048，包含负的 preroll 事件。raw 末尾另外 2,816 个样本
被 presentation duration 排除。因此历史同配置的 2,079 组合偏移可分解为 edit 2,048
与参考格式保留 31；它不是一个新增的通用 priming 常量。本轮没有扩展 MP4/edit 支持。
