# 实施路线图

路线图按“每阶段都能独立验证”组织，不以一次性完成完整 AC-4 解码器为前提。

## M0：文档与工具链冻结

交付物：

- 项目范围、架构、输出契约和规范基线。
- DAMF 测试案例描述格式。
- DAMF → ADM BWF → AC-4 的可重复命令行流水线。
- 首个 A-JOC bootstrap 样本的 provenance 与 inspection。

退出条件：同一案例可重复生成结构一致的 AC-4，所有工具版本和 hash 可追踪。

**状态：已达成。** 规范版本与哈希、向量来源、工具指纹和验证边界均已固化；后续实现结论持续回写到本文、测试策略与规范追踪矩阵。

## M1：容器、同步与 trace

交付物：

- raw AC-4 sync frame 迭代器。
- MP4 `ac-4` sample entry 与 `dac4` 解析。
- sample table、PTS、priming 和 edit list 适配。
- JSON trace CLI。

退出条件：能够在不解码 PCM 的情况下完整枚举 bootstrap 样本，并与 Bento4、MediaInfo 和 ffprobe 的可用字段交叉核对。

**状态：已达成，并于 2026-07-27 复核。** `scripts/cross_check.sh` 强制要求 ffprobe、Bento4 与 MediaInfo 的关键字段一致；检测到 GPAC 时增加第四路核对。工具缺失、字段缺失、TOC 解析失败或容器/码流不一致均使门禁失败。

同一码流的两条定界路径独立给出一致结果：容器 sample table 与 `Annex G` 裸流 sync frame 在帧数、负载字节、`b_iframe_global` 帧数与 `sequence_counter` 序列上逐项相同。

CLI 遍历全部 `trak` 并以 `stsd` 中的 `ac-4` sample entry 选择轨道；DTS、`ctts` 映射后的有符号 media PTS，以及应用 edit list 后的呈现时间分别保留。程序化集成测试固定了“视频轨在前、AC-4 轨在后”和首帧负 PTS 的回归行为。

需要注意帧数存在两种口径：容器 sample 总数为 143，而按 edit list 呈现区间计为 141，二者相差首尾各一个不完全落入区间的帧。比较时必须声明用哪一种，混用会得出错误结论。

## M2：TOC 与场景拓扑

交付物：

- bitstream version、frame rate 和 sample count。
- presentation、group 与 substream 数据模型。
- channel-based、direct-object、A-JOC 路径识别。
- 配置代次、随机访问和 reset 状态机。

退出条件：自生成结构案例均能得到稳定、可序列化且可回归的拓扑结果。

**状态：已达成。**

`ac4_presentation_v1_info()`、`ac4_substream_group_info()` 与三类 `ac4_substream_info_*` 已实现，精确覆盖 `bitstream_version = 2`。版本 0 与 1 走尚未覆盖的 `ac4_presentation_info()`；当前规范未定义大于 2 的语法。两端都显式拒绝，不把未来版本当作 v2 猜测性解析。

**编码路径判定完成：默认 profile 只产生 A-JOC。** 依据是 `b_channel_coded = 0` 且 `b_ajoc = 1`，两个案例全部 143 帧无例外。同时解释了参考解码器 21 个输出槽位的来源——`n_fullband_upmix_signals = 20` 加上单独声明的 LFE，即码流自身声明的值，而非解码器固定容器。详见测试向量策略 9.2a。

**「这套工具链只出 A-JOC」已被 IMS profile 推翻（M4 期间）。** 同一条母版改用 IMS profile 导出的两个 256 kbps 产物是 **channel-based**：`b_channel_coded = 1`、`ch_mode = 6`（`7.1_3/4/0.1`）、0 个对象、无 OAMD substream、`md_compat = 0`。`legacy` 变体多一个 `presentation_version = 1` 的 presentation，把同一个 substream 描述成 stereo。被推翻的是判定的**外推范围**，不是判定方法——9.2a 对 direct-object 的结论不受影响，那条至今没有真实样本。这也兑现了 9.2e 早就写下的限制：结论只限定当时的母版与工具配置，不外推到别的 profile。`ch_mode = 6` 由此第一次有了真实样本，此前只有构造码流的分支覆盖。详见测试向量策略 9.2j。

拓扑没有等价的外部工具可比，因此校验用两类独立证据：

- **码流自洽**：`payload_base` 与 `substream_index_table()` 必须与帧长相容；presentation、EMDF、OAMD、音频与 HSF 引用经范围校验后，必须恰好覆盖索引表的下标集合。逐位解析错一位即破坏该排列。
- **容器交叉**：Bento4 从 `dac4` 读出的 codec string 后两段（`presentation_version`、`mdcompat`）与本实现的 DSI 解析一致；本实现再按 effective presentation ID 将 DSI 与首帧 TOC 的 version、`md_compat`、group 路径及 A-JOC 对象数闭合，不依赖 presentation 数组顺序。该门禁先覆盖 A-JOC/direct-object；含不透明 v2 DSI 的 Channel-based 按已约定边界只记录。

真实码流原本只覆盖 A-JOC 一条路径；**channel-based 现已有真实样本**（见上文与 9.2j），direct-object 仍只有构造码流的单元测试覆盖，那是分支覆盖的下限，不能替代真实样本。默认 profile 内部的实验结论仍然成立：低至 256 kbps、以及纯 bed 零对象的输入，均未触发另两条路径（见测试向量策略 9.2e）——换 profile 才会。

**随机访问、配置代次与 reset 状态机：**

- 随机访问点判定不以 `b_iframe_global` 为准。该标志按 Part 2 只覆盖每个 presentation 的首个 substream，因此完整起解点还要求 `b_audio_ndot`、`b_oamd_ndot` 与 `b_pres_ndot` 全部为真；只满足前者的帧标为「仅音频可起解」。实测 7 个完整起解点与容器 `stss` 的 7 个同步样本逐帧吻合，构成又一条独立交叉验证（见测试向量策略 9.2b）。
- 配置代次由完整规范化拓扑指纹的变化界定：包含 program、presentation/group 固定引用、声道模式、A-JOC 配置和 LFE 等实际配置，只排除 ndot、`payload_base`、substream 尺寸、EMDF 保留填充及 EMDF payload 的逐帧路由。DME 流会在携带 payload 时临时增加第 4 个索引表项、无 payload 时回到 3 个；指纹按固定 presentation/audio/OAMD/HSF 映射跨度计算，三条 DME 全流仍各为 1 代。
- reset 状态机在首帧、配置变化、规范定义的来源变化、解析失败或外部不连续后挂起重置，只在下一个完整随机访问点执行。当前案例各有 1 次初始 reset，无等待帧，结束时无挂起状态。
- 解码延迟按表 81 解释后为 5 帧。`wait_frames` 的原始码字在不同 `frame_rate_index` 下含义不同，规范 `4.3.0` 要求引用解释值，因此码字不对外暴露。
- `sequence_counter` 不是普通的 10 比特回绕计数器：规范定义 `1020 → 1` 为正常回绕，前值 0 后的任意非零值为 splice 恢复。当前 `1019, 1020, 1, …, 141` 全程连续，来源变化为 0；该字段仍不可用作帧序号或时间基准。
- **`sequence_counter` 与配置指纹都不是充分的来源变化指示器。** 拼接向量显示：两条同配置流在同一帧下标处切换时，计数恰好衔接、指纹不变，一次真实换源不留任何痕迹。安全起解只能依赖完整随机访问点加容器层的不连续信号，见测试向量策略 9.2d。

## M3：OAMD 与时间线

交付物：

- OAMD 字段解析和原始量化值保留。
- 跨帧状态延续。
- 一帧内多次更新和 ramp 表示。
- seek/discontinuity 后状态完整性标记。

退出条件：静态、阶跃、连续运动和 reset 案例的元数据时间线符合母版意图与码流量化结果。

**状态：已达成。逐对象位置随 M4 解锁，两条此前悬空的结论也一并落定。**

载荷侧 `oamd_substream()` 已完整解析，OAMD 元素的语法实现（`object_info_block`、`object_basic_info`、`object_render_info`、`trim`、`bed_render_info`、`headphone`）对两条编码路径通用。逐对象字段公开原始码值；`trim` 与 `bed_render_info` 当前只公开结构性字段，其余字段按语法消费。`Ac4Topology::substream_payload()` 按 `TS103190-1:v1.4.1:4.3.3.12` 的 Pseudocode 1 定位载荷，是 TOC 与载荷之间的桥。

**曾经受阻的原因是规范布局，不是实现取舍。** `TS103190-2:v1.3.1` 表 7 规定：`b_ajoc` 为真时，逐对象动态数据位于 `audio_data_ajoc`，排在 `var_channel_element()`、`ajoc()` 与 `ajoc_dmx_de_data()` 之后。M2 已判定默认 profile 只产生 A-JOC，因此取得逐对象位置与增益必须先具备频谱前端的比特解析能力，即 M4。该路径的 core 与 full 两套动态数据现已各自对应一份 `OamdState`——两侧的对象集合不同（下混信号数对上混对象数），状态不能共用。

已达成的交付物：

- 原始量化值保留：直接对象路径的基本信息、位置、区域、宽度、屏幕、距离、散度、扩展精度与耳机字段均可从 `metadata_blocks()` 读取。
- 跨帧状态延续：`OamdState` 实际合并 `REUSE`/`PART_REUSE`、增益复用和差分位置；状态按 OAMD substream 隔离，应用失败保持事务性。`num_obj_info_blocks` 在时间数据缺席时显式沿用前序值，无前序值时报错而非假定 0。
- seek 后状态完整性：seek、配置变化、不连续及解析失败会清空相应历史；I-frame 首块 `b_no_delta` 为真时语法上不传输 reuse 标志，已由单元测试固定。
- 验证：`oamd_substream()` 的 `byte_align` 残余必须小于 8，作为载荷边界自检；两个案例 286 帧全部通过，残余上界 6 比特。CLI 统计以帧为单位去重，并逐帧核对 `oamd_common_data` 与 `stss` 成员关系，失配数必须为 0。
- reset 状态机的真实数据覆盖：`scripts/make_splice.py` 由两条已编码轨道构造拼接裸流，`scripts/splice_check.sh` 门禁验证来源变化、reset 事件与等待随机访问帧数。此前这三项在单一来源的向量上恒为 0。裸流路径同步升级为运行完整拓扑与 OAMD 巡检。

随 M4 落定的交付物：

- **一帧内多次更新：编码器不产生，不是解析不到。** 此前只知道 group 级 `oamd_timing_data` 声明 1 个块，怀疑真正的更新藏在 `audio_data_ajoc` 里。现在两处 `oamd_dyndata_single()` 都解出来了，八条流的 `num_obj_info_blocks` **恒为 1**，core 与 full 两侧皆然。`probe_subframe_updates` 源端每帧四次更新（192 个 `audioBlockFormat`，间隔 512 采样）在编码时被降到每帧一次；它的位置确实逐帧变化（50 帧 43 次），只是不再有帧内细分。这与编码器忽略 `rampLength` 是同一类行为。
- **元数据时间线与母版意图一致，轴映射就此标定。** `probe_axes_single_object` 的六段轴极值逐段对上：

  | 母版段 | DAMF 位置 | 解出的量化位置 | 段边界 | 解出的帧 |
  |---|---|---|---|---|
  | X-min | (−1, 0, 0) | (0, 31, 0) | 0 | 0 |
  | X-max | (1, 0, 0) | (62, 31, 0) | 48 000 | 27 |
  | Y-min | (0, −1, 0) | (31, 62, 0) | 96 000 | 50 |
  | Y-max | (0, 1, 0) | (31, 0, 0) | 144 000 | 74 |
  | origin | (0, 0, 0) | (31, 31, 0) | 192 000 | 97 |
  | Z-max | (0, 0, 1) | (31, 31, 15) | 240 000 | 119 |

  **X 与 Z 同向，Y 反向**：DAMF 的 `y = +1`（前）映射到量化码 0，`y = −1`（后）映射到 62。中心恒为 (31, 31, 0)，与 `ObjectRenderState::defaults()` 一致。这正是该向量设计时要标定的量（`case.json` 的 intent 首条）。

  每次换段后位置在 3 至 4 帧内过渡到位（如 45 → 59 → 61 → 62），段边界与过渡起点逐段对齐。**该过渡是编码器的一阶平滑，每帧走完剩余距离的约八成**，在段边界与帧边界对齐的 `probe_ramp_control` 上量得 81.7 %–81.8 %；段长不足时位置追不上母版就已换段，因此 ramp 案例的 x 始终在 `2…60` 之间摆动。另有一类规律的 (0, 0, 0) 偏移出现在每段后半——源端每段只有前 24 000 采样发声，编码器把静音期的对象泊在原点角。

  `scripts/trajectory_check.py` 把这张表固化为门禁：由 `case.json` 生成母版逐帧轨迹，与解出的轨迹逐轴比对形状与到位，六个含对象的案例全部通过，动态对象一致落在 full 侧的对象 1。见测试向量策略 9.2i。

- ramp 表示：**编码器忽略源端 `rampLength`**，结论不变。`probe_ramp_lengths` 与其 ramp 全零的对照案例 `mdat` 逐字节相同，`ramp_duration` 恒为 2 048。`ramp_duration_code` 的其余分支只能靠构造码流覆盖。

trace 的 `result.validation.ajoc.observations.position_timeline` 记录上混侧逐块位置变化（每项携带 substream、object 与 block 下标；上限 4 096 条，超出置同级 `position_timeline_truncated`），`first_positions` 则按物理 substream 保留首次成功解析的快照，上表可直接由它们复核。

**位置时间线已由外部参考解码器复核，664 个对照点全部通过逐轴绝对差 `< 1e-9` 的判据。** 参考 AXML 由 DRP 4.3.0.19350 arm64 runtime 经本地适配后导出；两份 `axml` chunk 的 SHA-256 均与实验记录一致，个人适配工具的名称与调用路径不入库。1992 个坐标中 831 个浮点严格相等，实测最大绝对差为 `4.838629497072588e-13`；其余差异符合 AXML 小数点后最多 12 位的格式化结果，因此结论仍是容差一致而非严格相等。参考侧取重建 ADM 的 `audioBlockFormat` 位置序列，按对象分组后逐条按序配对。合成探针 49/49；真实母版 615/615，覆盖 19 个动态对象与 157,6 秒全程；两侧的动态对象集合都是 01–20 缺 05，对象 05 在两侧都全程不动——说明对得上的不只是数值，还有对象编号与 substream 归属的读法。唯一的条数差是对象 3 多一条：前 72 条值都通过同一判据，多出的末帧事件加时间偏移后越过媒体末尾，被参考侧丢弃。

**上表的轴映射因此有了第二个独立来源。** 它原本由母版意图（`case.json`）标定，本次用参考解码器复核，两者给出同一组常数 `X = (c−31)/31`、`Y = −(c−31)/31`、`Z = c/15`。参考侧的 `rtime` 恒比我方帧起点晚 2 400 采样，恰等于一帧加参考解码器元数据头里的常量 352——自洽，但没有独立依据说明为何是一帧，故只作解释不作结论。

**这次对照没有覆盖的部分同样要写明。** 增益、优先级与 activity 一条都没比；更要紧的是**核心带 PCM 无法用这个 oracle 验证**——它最浅的出口是完整解码后的对象 PCM，中间层不暴露。M4 那份逐位冻结基线的地位仍然只是防回归，不是防错。数值、口径与限制见[参考解码器位置对照](experiments/reference_decoder_position_crosscheck.json)。

详见测试向量策略 9.2c 与 9.2h。

## M4：音频核心标量基线

交付物：

- 规范所需基础音频工具的标量实现。
- 明确的工作区和无逐帧分配路径。
- 数值与频域单元测试。
- channel/core PCM 的首个可听输出。

退出条件：基础声道/核心配置连续解码，无未解释的帧漂移，并建立冻结的数值回归基线。

**状态：已达成。** 比特流解析前端与核心带 PCM 标量重建已完成；A-SPX 已从码流参数贯通到真实声道路径的 `Q_out,ASPX`，并可在已确认的动态 A-JOC、长帧、无活动压扩、无交织子集上导出终端诊断 PCM 与 core 对象输出。生产音频原语保持 `no_std`、调用方工作区和无逐帧分配；未覆盖路径继续 fail-closed，不把本里程碑解释成全 profile 支持。

当前已从 `ac4_substream()` 贯通 `var_channel_element()`、ASF、A-SPX、A-JOC、`audio_data_ajoc()` 与两套 OAMD 动态数据；12 条逐位基线媒体共 1 140 帧全部精确落在 `audio_size` 边界。量化谱线已经反量化、缩放、解组并经 IMDCT 还原为连续核心带 channel PCM，真实声道路径也已驱动 A-SPX，并按 `Pseudocode 14a` 产出 A-JOC 输入顺序的 QMF/PCM；core PCM 与第一份 OAMD 配对的固定网格 CAF 已交付。core 与 A-SPX 两段各 12 条逐位基线、完整音频门禁及轨迹门禁共同关闭了 M4 的连续解码、帧漂移与数值回归退出条件。full 模式的 A-JOC 上混、LFE `Pseudocode 15` 插回和 full 对象 PCM 归入 M6；`Ac4SceneFrame` 与渲染前场景组装归入 M5。

**`5.1.3` 的量化重建与缩放已完整实现。** `Pseudocode 21` 的 DPCM 累加是纯整数的，八条流 41 693 个频带全部落在 `5.1.3.2` 规定的 `0…255` 内，实测取值 `77…159`。取值域判据的强度已量化，见规范可追踪性 5.14。

后两步——增益 `2^((sf−100)/4)` 与反量化 `sign(q)×|q|^(4/3)`——按 ADR-0002 落地：反量化表由构建脚本以 `u128` 整数判据正确舍入并核对完整位表摘要，增益拆成位构造的 `2^q` 乘四个 `2^(r/4)` 常量。这两步没有比特可数，落点判据完全失效，判据换成完全立方数的整数恒等、增益单调性与常量的正确舍入，八类注入全部被捕获（规范可追踪性 5.15）。八条流约 99 万条谱线走完整条链，非有限值 0 个，峰值 `1.0×10⁷`–`1.9×10⁷`。

**`5.1.5` 谱解组已完成。** `Pseudocode 25` 把码流的「组 → 频带 → 组内窗口」还原为「窗口 → 频率升序」，只搬运不计算，因此判据是排列的双射性；实测多窗口占 0.3 %–9.5 %（最大 16 个窗口），这一步在真实数据上不是恒等变换。八条流解组 11 030 528 条谱线，非零数零失配、能量最大漂移 `4.2×10⁻¹⁶`。见规范可追踪性 5.16。

**这条基线证明的是「没有意外改变」，不是「正确」**——不是因为缺参考解码器，而是**输出层级不可比**：本基线取的是 A-JOC 下混信号的核心带 PCM，一个中间量，任何参考解码器都只暴露走完 A-SPX 与 A-JOC 上混之后的结果。差分裁决要等这两步落地才接得上；届时按规范可追踪性第 7 节的清单逐条核对。它填的是一个真实缺口：此前全部门禁都是结构性或统计性的，改掉一处舍入而不改变落点、计数与峰值量级时无人报警。注入实测：只在窗口组数 ≥ 5 的帧上把增益扰动 1 ulp（这种成帧只出现在真实码流里），**单元测试 0 失败、`audio_check.sh` 通过，而基线八条全部报出摘要变化**。`probe_ramp_control` 与 `probe_ramp_lengths` 的 `payload_sha256` 相同，两者的 PCM 摘要也相同，这是基线自带的一条确定性交叉核对。编码媒体不入库，故数值比较是 fail-closed 的本地门禁；CI 覆盖脚本的缺件失败、路径约束与原子更新逻辑。

**`5.7.3`/`5.7.4` 的 QMF 滤波器组已落地。** 64 子带复数分析与合成两条伪码都已实现，共用表 D.3 的 640 抽头原型窗。窗与 Huffman 码本同源，取自校验过的随附 C 表，不经人工转写；`build_support/spec.rs` 负责 `float` 数组解析，并核对两条与摘要无关的结构判据——镜像仅在 128 的倍数处反号，每个多相相位的 `Σ_k QWIN[64k+p]² = 1`（实测偏差 `2.8×10⁻⁷`）。调制相位化简为 `2π·(2sb+1)·m / 512`，按 ADR-0003 的规则生成 512 点整圈表，摘要 `4e7f81b7…` 已由 100 位十进制独立复算锚定。

**`5.7.6.3.5` 的反量化与立体声解码已落地。** `Pseudocode 82`/`83`/`84` 把 `qscf` 变成线性标度因子。规范 `3.1` 把标度因子定义为**能量**，这一条把两档量化步长钉死（能量域取 `10·log10` 才得 1,5 dB 与 3,0 dB），并推出伪码没写明的 `qscf/a` 是实数除法——整数除法会让 1,5 dB 档退化成 3 dB 档。指数只可能是整数或半整数，因此不需要通用 `pow`：`2^n` 由 f32 指数域直接构造，半整数部分乘 `core` 的 `√2`；越出正规数范围一律报错，不产生 `inf`。平衡式立体声有代数恒等式 `scf_a + scf_b = 2·scf_mono(qscf_a)` 可跨 `Pseudocode 84` 与 `82` 互证。十二类注入全部被捕获；其中「两个分母互换」只有单调性判据抓得到，而「`PAN_OFFSET` 当成 6」一开始全部漏掉——居中用例用了实现里的常量算期望，改成从伪码抄字面量 12 才成立。见规范可追踪性 5.25。

**事务性契约是逐次收紧出来的，五次修正堵的是同一类漏。** 凡能由调用参数判断的错误，都在工作区清理与跨帧状态推进之前返回——它们的补救办法是「修正后用同一帧重试」，而 `prepare_frame()` 会清掉上一帧的 `y`，十一个状态里又有七个是随通路就地推进的（只有包络、正弦与两个游标先算副本、成功后才提交），此时报错等于让调用方拿着半推进的状态重试。曾经越过这条线的有：表推导排在清理之后、区间校验排在 `prepare()` 之后、chirp **取值**校验留在 `chirp_factors` 内部、`CarryoverMismatch` 从组装内部抛出、包络与正弦在组装之前提交。`master_reset` 的判定与提交也据此拆开：查询取 `&self`，重试与逐声道询问都拿到同一份判定。见规范可追踪性 5.38。

**接线的第一段已落地：信号落点与驱动决策。** `var_channel_element()` 分两段传输，两段的元素数不同，故 `VarChannelElement::signals()` 逐路给出「核心带 PCM 在哪、A-SPX 参数在哪」。`coding_config = true` 时两段的分组真的不一样——信号 6、7、8 在声道侧属同一个 `three_channel_data()`，在 A-SPX 侧分属两个元素；LFE 则占声道侧的第一个元素而**不占** A-SPX 下标。按元素下标一一对应会静默配错。

`aspx_jobs()` 再把落点变成驱动决策：LFE 做 QMF 分析后留待 `Pseudocode 15` 重新插入，不进入 A-JOC；SIMPLE 全频带信号同样跳过 A-SPX，但其 QMF 输出仍进入 A-JOC；其余按 `aspx_balance` 决定单路还是并对。**这一步是本层唯一会静默出错的判断**——`Pseudocode 84` 要两路 `qscf` 一起反量化，拆开算出的标度因子是错的，而两路照样各有输出、各有峰值，落点与统计判据一概看不出来。逐元素的 balance 位在解析成功时固化进 `VarChannelElement`，作业接口不再接收可跨帧复用的工作区，因此同形状但标志相反的另一帧不能改写既有决策。判据是双射与展平相等：期望序列由解析器填好的工作区生成，覆盖 1…16 路 × 有无 LFE × 两种编码配置 × 两档 `aspx_balance`，并另行钉住工作区改写不影响摘要以及 SIMPLE/LFE 的下游分流。

**A-JOC 的输入顺序不是传输顺序（`Pseudocode 14a`）。** 勘查 LFE 去向时才看到 `5.7.2.1` 的这一段：`m'_fb > 3` 时**最后 2 或 3 路要挪到 A-JOC 输入的最前面**，`n_offset = 2 + (m'_fb mod 2)`。以 `n_dmx_signals = 9` 带 LFE 为例，A-JOC 输入是 `[s6, s7, s8, s0…s5]`。**搞错了不会有任何一处报错**，只是每个对象都从错的下混信号重建。`VarChannelElement::ajoc_input_order()` 给出这个置换，判据的期望表照伪码手推、不引用实现里的 `n_offset` 算式；另两条钉住它是全频带信号的置换，以及 LFE 只是被剔除、不改变其余各路的相对顺序。注入 10 类缺陷全部被捕获、5 类等价变体沉默，其中「阈值 `m'_fb > 3` 改成 2」实测**惰性**——`m'_fb` 取 2 或 3 时 `n_offset` 恰等于 `m'_fb`，重排退化成恒等，1…16 逐项相同；那道判断真正防的是 `m'_fb < 2` 时 C 里的下溢。此前用 `Pseudocode 15` 的 L/R/C 标志给领头输入补标签，现已撤回：那三个标志属于 A-JOC **输出**后处理，不能反推通用输入矩阵的声道标签；这不改变 `Pseudocode 14a` 直接规定的置换。

**LFE 的 QMF 域相对对齐已判读：并回之前补 `ts_offset_hfgen` 个时隙。** `5.7.6.5.3` 把 `δ_ASPX = ts_offset_hfgen` 称作 A-SPX 引入的总延迟，`4.8.3.11.1` 与 `6.2.10` 又把 LFE 排除在 A-SPX 之外，而 LFE 要按 `Pseudocode 15` 并回的那份 A-JOC 输出已经吃过这段延迟——不补就快 192 或 384 个样本。`Pseudocode 15` 对 LFE 只有直接赋值，说明输入接口要求它预先对齐；`5.7.3.6.1` 的 dry 分支也在同一 `ts` 直接使用 A-JOC 输入，decorrelator 的延迟只属于 wet 分量，并非统一的 A-JOC 输出延迟。规范没有明写 LFE 延迟，故仍按判读登记在规范可追踪性第 7 节，但跨条款依据已经闭合。

P1 `5.7.1` 的全局 6 个 QMF 时隙改作另一层问题处理：它描述终端 QMF 的公共/绝对时间轴，不能消除 LFE 旁路相对 A-SPX 通路少掉的 `δ_ASPX`。短帧下它与表 192 的 3 时隙如何组合仍未决；`export-aspx-pcm` 因此不替规范做默认选择，显式拒绝 SIMPLE 与 1 024 及以下短帧，只放行 `δ_ASPX = 6` 的 1 536/1 920/2 048 样本长帧。这不改变 LFE 分支该补 `ts_offset_hfgen` 的结论。

**`Pseudocode 15` 插回位置的三个标志已关闭为实现未决项。** 三个名字在 P2 V1.3.1 全文确实只出现于伪码，规范存在编辑脱漏；但 `Qout_AJOC` 的 `num_umx_signals`、`6.2.1.9` 的两份独立分配、`6.3.2.8` 对 core/full 对象位置的说明，以及表 63–66 的 L/R/C 映射形成唯一闭合：从 full-decode 的 `upmix_assignment` 派生，`pos_lfe` 为其中 L/R/C 的存在数量。`ObjectAssignment` 现保留这三个派生值，`SubstreamInfoAjoc::lfe_reinsertion_position()` 明确只取上混侧。固定码、两套标志、逐声道列表、dynamic-only/ISF 及 core/full 分配相异均有构造判据；真实八条流仍只覆盖 dynamic-only 的 `pos_lfe = 0`，故该结论移入规范可追踪性第 7 节等待外部对象 PCM 裁决。

**元素级驱动已落地：`element_drive::drive_element`。** 按路由层的三份答案逐条执行，把每一路的 `Q_out,ASPX` 写进调用方的 A-JOC 输入缓冲。三条去向的延迟各不相同——经 A-SPX 的各路与 A-SPX 元素里的 LFE 都带 `δ_ASPX`，SIMPLE 元素一格都不带。工作区只要两份（平衡式一次用两条），跨帧状态逐声道一份。整元素在第一路启动前统一核对公共合法帧长、状态与中间量容量、A-SPX 数据/配置的存在性与逐路访问、路由和 A-JOC 落点；这些结构错误不再留下「前几路已推进、后一路才失败」的半帧。进入底层通路后的内部错误仍沿用其契约：丢弃整元素输出、重置状态并从随机访问点重新起解。

`var_codec_mode` 的跨帧变化先显式拒绝。多处状态按「上一个 A-SPX interval」定义，但规范没有说明 SIMPLE 插在中间时是冻结、清空还是用旁路 QMF 推进；冻结输出延迟线会在恢复 A-SPX 时重放切换前的旧时隙。`ElementChannelState` 因而提交上一帧模式，变化时返回 `CodecModeChangeRequiresReset`；调用方只能在随机访问点整体重置后以新模式起解，不做静默的局部清零判读。该缺口登记在规范可追踪性第 6 节。

判据九条。前三条各钉一件事：LFE 与经 A-SPX 的各路走同一条时间轴、SIMPLE 一格延迟都不加、输出按 A-JOC 输入顺序而非传输顺序摆放；其余六条覆盖逐路帧长不一、SIMPLE 使用表外帧长、平衡式短工作区、LFE 先行时缺 A-SPX 数据，以及双向 codec mode 变化与显式重置。缺数据的两条分别钉住首个元素缺失，以及前一个元素合法而后一个缺失时仍报告真正下标且不推进任何声道。**对齐判据只能比低带**：`Q_out = Q_in(延迟后) + Y`，而 f32 下 `(a + b) − b` 不恒等于 `a`，实测在 `sbx` 处差 8×10⁻⁶ 的相对量；低带的 `Y` 恒为零，等式才是精确的，高带另用「`Y` 非零」单独钉住——否则那一路根本没走 A-SPX 也照样通过。原三条的注入 7 类缺陷全部被捕获、4 类等价变体沉默（含一条不可达的尾部清零）。

**`export-aspx-pcm` 已接通并迁到 Scene Session：真实码流走完 A-SPX。** 命令把 bounded AU 交给 `Ac4DecoderSession(DecodeMode::Core)`，默认以 `AutoUnique` 解析 presentation，也接受显式零基 `--presentation`，再由同一 A-JOC engine 将核心带 PCM 交给 `element_drive` 并逐路做终端 QMF 合成；batch adapter 仅恢复旧 `±32768` 位型、轨序和 MP4 edit 投影。它是受限诊断出口：只放行 A-SPX 模式、1 536/1 920/2 048 样本长帧、未激活 companding 且未使用 FIC/TIC 的已确认子集；SIMPLE、短帧、活动压扩或交织分量都在数值通路前拒绝，并使用 `unsupported.coding_path` 而非把合法语法误报为 `parse.failed`。当前 12 条 A-JOC 实测流全部走通；最初语料中 `probe_bed_only` 256K 的第 0 路 RMS 由 5 632 升到 6 363、峰值由 8 087 升到 12 764——高频确实被补上了。channel-based 的两条仍报 `unsupported.coding_path`。

**P1 `5.6`/`5.7.2` 的 frame alignment 已补齐。** 旧链把同一 raw frame 的 A-SPX 控制直接套到当前 IMDCT PCM，漏掉表 188 同时要求的 `d_pcm` 与 `d_ctrl`。48 kHz 音乐档应让 PCM 延迟 352 samples、控制延迟一个 2 048-sample codec frame；漏掉后高频控制相对低带早 `1 696` samples。现在逐声道环形缓冲执行八档 `d_pcm`，逐 substream FIFO 在 1/2/4 帧后释放带所有权的控制快照；首份控制到期前只预热 QMF/低带/TNA/输出及合成历史，不提前消费包络、噪声或音调状态。当时九条 A-SPX 逐位基线已按规范性变化重冻，当前已扩到十二条。一份本地私有音乐参考素材 q2 的 1024 点 STFT 能量互相关中，修复前相对 DRP 的低/高频 lag 为 2 432/4 096 samples，残差 1 664；修复后两者均为 2 048，残差 0（hop 64）。共同的 2 048 起点差与带间同步无关，暂不把 DRP 当容器 priming 的时间轴 oracle。见规范可追踪性 5.44 与[实验记录](experiments/aspx_frame_alignment_observation.json)。

**`5.1.4` 谱噪声填充推迟。** `b_snf_data_exists` 在八条流上恒为假，且实现需要任意实数的 log2/pow2 与正态随机数发生器——三样都在 ADR-0002 的覆盖之外。见规范可追踪性 5.17。

**数值格式已定，见 [ADR-0002](decisions/0002-numeric-format-for-reconstruction.md)**：频域中间量与 PCM 用 `f32`、变换累加器用 `f64`，运行期超越函数一律查表或位构造，禁用 FMA。反量化表由 `u128` 整数判据正确舍入；变换根由 ADR-0003 允许的构建期 `libm = "=0.2.16"` 生成并冻结摘要，目标侧仍为零外部依赖。实测支撑：八条流约 99 万条谱线的 `|quant_spec|` 峰值 8 084，贴着规范上限 8 191，故反量化表必须覆盖完整的 `0…8191`；`scaled_spec` 的实测动态范围约 `2^38`，规范全域约 `2^81`，两者都在 f32 的指数范围内，选型的争点是精度而非范围。

首个增量先完成了 `ac4_substream()` 框架与 `metadata()`：

按 `TS103190-1:v1.4.1:4.3.4.1` 用 `audio_size` 跳过音频数据直达 `metadata()`——这是规范自带的捷径，NOTE 明确「使解码器无需解析音频数据即可直接访问 metadata」。判定条件是解析后恰好落在 substream 末尾，该等式由 `substream_index_table()` 独立声明的长度支撑，八条码流 0 次失败。

由此得到一条与解码器无关的码流事实：`sus_ver` 在 `bitstream_version = 2` 下恒为 1，`dialnorm_bits` 只在 `sus_ver == 0` 传输，因此本项目的码流不含 dialnorm；实测连 `substream_loudness_bits` 也未传输。**整个音频 substream 不含任何响度或 dialnorm 元数据。**（这条原本是为追查一个「15.0 dB 固定衰减」而查的，那个现象已撤回，见测试向量策略 9.6；本结论独立成立。）

**Huffman 码本已就位。** 附录 `A.0` 规定码本以规范随附 zip 给出，因此 84 张码本、4 917 个符号完全不经人工转写，由构建脚本从校验过的 C 表生成，见规范可追踪性 5.1。这消掉了整个 M4 中最难被比特级门禁发现的一类错误——`ramp_duration_table` 那次说明查表出错不改变比特消耗量，没有任何落点等式抓得住。

**解析主体在实现前探明的范围比预期大。** 初期探针读出 `var_channel_element()` 的 `var_codec_mode`，三档码率、全部帧恒为 A-SPX（表 77）：

| 448 kbps | 7 | 3 | 否（> 5） |

**ASF 的表格层已就位**：附录 B 的 15 列共 538 个偏移值、表 106 的比特宽度、表 99–105 的变换长度、表 109–110 的分组比特数，以及表 A.2–A.15 的码本元数据。这些值由 `scripts/generate_spec_tables.py` 从用户本地的官方 PDF 生成，位于 `spec-tables` feature 下，不进入版本控制或 crate 包；附录 B 另由 `scripts/check_sfb_tables.py` 逐值反向核对，见规范可追踪性 5.2。

**ASF 的成帧层已就位（44,1/48 kHz）**：`asf_transform_info()`、`asf_psy_info()`，以及 `Pseudocode 2`–`5` 的窗口分组、`get_max_sfb(g)`、`get_transf_length(g)` 与 `sect_sfb_offset[g][sfb]`。工作区定长，推导过程不分配。解析入口显式接收采样频率；96/192 kHz 的规范表尚未导入，因此在读取码流前返回不支持错误，不会静默套用 48 kHz 表。

这一层在真实码流落地之前先拿到了一条**独立于码流的判据**：`max_sfb` 取上界时谱线总数恒等于 `frame_len_base`——窗口必须无缝铺满一帧。16 种半帧组合 × 两种分组取值全部成立，且推出的 `num_windows` 恰好覆盖 `4.3.6.2.6` NOTE 列出的 11 个取值、不多不少。两处注入实验确认判据有效：把半帧归属的 `>=` 写成 `>`，或省略 `Pseudocode 3` 在半帧交界处的强制断开，铺满等式立即失败。

**ASF 的熵编码层已就位**：`sf_data(ASF)` 的四个元素与 `5.1.2.2` 的基数分解、符号位、码本 11 转义扩展。它们需要附录 A 的码本，因而落在 `audio-decode` feature 之内。工作区约 14 KiB，按通道复用，解码不分配。

这一层的判据比成帧层弱——没有「铺满一帧」那样的精确等式——因此依靠三类互不重叠的约束：

- **基数分解可逆**：`Pseudocode 19` 的分解对全部 11 张码本、1 241 个符号逐一还原。位序或除数写错立刻暴露。
- **标度因子与噪声填充条件互补**：表 41 要求「有码本且非全零」，表 42 要求「无码本或全零」，二者并集为全部频带、交集为空。因此每个频带至多一个差值，且只有首个非零频带两者皆无。
- **手工构造帧落点精确**：构造可验算的载荷跑完四个元素，消耗比特数必须与构造长度相等。

`ext_decode()` 的上界由规范交叉推出而非假定：`Pseudocode 20` 给出比特数 `1 + N_ext + (N_ext + 4)` 与值域 `[2^(N_ext+4), 2^(N_ext+5) - 1]`，表 40 标注该元素 5 至 21 比特，`5.1.3.1` NOTE 1 规定幅度上限 8 191——两条独立表述都把 `N_ext` 卡在 8。

三处注入确认判据有效：颠倒基数分解位序、把 `sect_len` 起始值由 1 改成 0、符号位不判非零而无条件读取，分别使 3、4、1 个用例失败。

**已知未覆盖**：高采样率扩展。表 39 在 `sect_end` 越过 `num_sfb_48` 时会把区段一分为二，但 `asf_psy_info()` 已将 `max_sfb` 限制在 `num_sfb` 之内，该分支在当前支持的配置下**可证不可达**，故未实现。导入表 B.2／B.3 时必须补上。

**声道元素层已就位**：`mono_data()`、`two_channel_data()`、`three_channel_data()` 与 `three_channel_info()`，连同 `sf_info()`／`sf_info_lfe()`、`chparam_info()`／`sap_data()`、`companding_control()`。至此 ASF 一侧形成闭环——从 `var_channel_element()` 调用的三个声道数据元素起，到每声道的量化谱线为止，全程可解析。

判据仍是落点：每个元素解析后消耗的比特数必须等于构造长度。三处注入确认它能区分容易读错的分支——LFE 误用 `n_msfb_bits`（6 位）而非 `n_msfbl_bits`（3 位）、`sap_data` 逐带传输而非两带一组、`b_enable_mdct_stereo_proc` 为真时误读两份 `sf_info()`，分别使 2、2、4 个用例失败。

两处显式拒绝而非猜测：`spec_frontend` 选中 SSF（`4.2.9` 的算术编码与附录 C 表格均未实现），以及不受支持的采样率。

`ChannelElement` 约 60 KiB，主要来自三个 `AsfWorkspace`，按元素复用；与 `AsfWorkspace` 同样在复用时整体清空，避免声道数减少时暴露上一个元素的尾部状态。

这条「整体清空」最初漏掉了 `spectra` 本身，而当时的复用用例没能发现：它断言的是 `spectrum(2).is_none()`，通过的原因是访问器按 `channels` 做了边界检查，而不是数据被清空了——两道防线只测到了外层那道。触发路径是**解析中途失败**：`self.channels` 在 `decode_channel` 之前就已写入，首声道谱数据截断时访问器会放行尚未写过的声道。现已补齐清空与对应用例。

**A-SPX 的表格与推导层已就位**：`5.7.6.3.1.1` 的两张模板子带组表、表 189/192 的时隙换算、表 126 的间隔类别、`Pseudocode 79` 的码本选择，以及 `Pseudocode 67`–`70` 推出的 `num_sbg_master`、`num_sbg_sig_highres`、`num_sbg_sig_lowres` 与 `num_sbg_noise`。枚举与码本选择不依赖外部表；PDF 表及其推导位于 `spec-tables` feature 下。

判据覆盖全部合法配置的笛卡儿积（两张模板 × 8 起始 × 4 终止 × 4 噪声 × 8 交叉偏移）：三张派生表的每个边界都必须取自主表、严格递增、末项等于 `sbz`，低分辨率组数等于高分辨率的一半向上取整。两处注入确认——`Pseudocode 69` 的奇偶分支互换、`Pseudocode 70` 的 `idx` 不累加，各使 2 个用例失败。

两处退化配置显式拒绝：低分辨率模板配合 `aspx_start_freq == 7` 与 `aspx_stop_freq == 3` 会把主表压成空表，`aspx_xover_subband_offset` 不小于主子带组数则会吃掉全部频带。

`num_sbg_noise` 的浮点对数改用等价的整数判据，精确而非近似，见规范可追踪性 5.4。模板表的核对盲区见 5.3——表 190/191 只覆盖得到偶数下标，故新增 `scripts/check_aspx_tables.py` 作为第二来源。

**A-SPX 的时频成帧层已就位**：表 194 的 `tab_border`、表 193 的 `noise_mid_border`、`Pseudocode 76` 的包络边界与 `Pseudocode 77` 的 `freq_res()`。

这一层原本被归为「重建」，实际是**解析所必需**：`aspx_freq_res_mode` 取 2 时逐包络的频率分辨率由时隙跨度决定，而分辨率决定 `aspx_ec_data()` 用 `num_sbg_sig_highres` 还是 `num_sbg_sig_lowres`，直接改变 Huffman 解码次数。它与频带表推导合起来才定出熵编码数据的循环次数。

判据里有一条跨表的巧合值得记：表 194 的五行 `num_aspx_timeslots` 恰好是表 189/192 换算出的全部取值，两张表来源无关却完全重合，因此互为转录判据。另一条同类：表 192 第三列 `ts_offset_hfgen` 换算到 A-SPX 时隙后在八行上恒为 3，正好是 `aspx_var_bord_left`／`aspx_var_bord_right` 这两个 2 位字段的上限——`5.7.6.3.3.1` 的正文与表 53 的字段宽度就此对上。

**A-SPX 语法层已就位**：`4.2.12` 的九个元素齐备。`aspx_int_class` 按表 126 的 1 至 3 位变长前缀码解析；`num_aspx_timeslots` 不超过 8 时 `aspx_framing` 的若干字段由 2 位退化为 1 位——按表 189/192，这只在 `frame_len_base` 为 512 与 384 时发生。

表 A.16–A.33 的 18 张码本随 `build.rs` 生成，`cb_off` **未进入实现**：12 张 DF/DT 表上 `cb_off == (codebook_length - 1) / 2` 恒成立，由码本长度直接推出，另有 `len_DF == 2 * len_F0 - 1` 佐证。这一处因此没有任何手工转录，见规范可追踪性 5.6。

判据仍是落点。六处注入里有两处首轮**全部通过**，暴露的是取值覆盖而非判据失效：所有用例都取 `aspx_freq_res_mode == 3`，高低分辨率两张表恰好不产生差异；`aspx_tic_present` 一律为 0，`aspx_hfgen_iwc_2ch()` 最复杂的那段从未进入。补测覆盖 `freq_res_mode` 的 0 与 1、时间交织的六种标志组合、频率交织的四种组合后，两处注入各使 2 项与 1 项失败。

跨帧状态由调用方持有：`aspx_config`、`aspx_xover_subband_offset` 只在 I 帧传输，`previous_stop_pos` 逐声道跨间隔延续。

**`var_channel_element()` 已就位**：P2 `6.2.4.4` 的三条分支齐备，ASF 与 A-SPX 两侧首次串成一个完整元素。声道数据与 A-SPX 数据**分两段传输**，元素数不同，故各自计数。

判据是全链路落点：`var_codec_mode`、`aspx_config()`、`companding_control()`、若干声道数据元素、若干 A-SPX 数据元素串起来，消耗的比特数必须等于构造长度。

这一层暴露出**跨帧状态的粒度**：`aspx_config()` 是元素级的一份，而 `aspx_xover_subband_offset` 由每个 `aspx_data_*()` 单独传输、`previous_stop_pos` 更是逐声道延续。原先把三者都塞进一个 `AspxState`，单个数据元素时无碍，多个元素共享就会互相覆盖。已拆开：`AspxState` 的粒度改为数据元素，`aspx_config` 交由 `VarChannelState` 持有，详见规范可追踪性 5.8。

工作区由调用方提供：一个 `ChannelElement` 约 60 KiB，最坏情形需要九个，合计约 540 KiB，放在栈上不现实。容量在读取任何比特前核对。

**A-JOC 的数据层已就位**：`6.2.5` 的 `ajoc()`、`ajoc_ctrl_info()`、`ajoc_data()`、`ajoc_data_point_info()` 与 `ajoc_huff_data()`。混合矩阵留在量化域，不反量化也不做时间插值。判据是落点，覆盖稀疏与非稀疏、时间与频带两个方向。

这一层最容易踩的是**与 A-SPX 的貌合神离**。两处 Huffman 数据语法几乎同构，但码本参数规律相反：A-JOC 的 `DF` 码本 `cb_off` 为 **0** 且与 `F0` 等长，而 A-SPX 的 `DF` 与 `DT` 都带一半偏移。另有表 79 的 `ajoc_quant_select` **0 为 Fine、1 为 Coarse**，表 78 的频带码**单调递减**，两处都与直觉相反。详见规范可追踪性 5.9。

顺带补上了一条两个模块共缺的判据：**码本映射必须按名字比对**。「互不相同」挡不住成对互换，落点判据对它无感（测试的构造侧与解析侧共用同一张映射表），而 A-SPX 的 `DF` 与 `DT` 长度相同，连长度关系都区分不开。现在两侧都用 `build.rs` 生成代码里的码本名作独立来源。

**对话增强与床信息已就位**：`6.2.3.5` 的 `ajoc_dmx_de_data()` 与 `6.2.3.6` 的 `ajoc_bed_info()`。

表 82 的 `de_dlg_dmx_coeff_idx` 是 1／4／5 三种码长的前缀码，四位码 `1111` 与五位码不冲突——后者的低四位只取到 `1101`。系数留在量化域，只保留 `n/15` 的分子，故不引入浮点。

`num_dlg_obj` 由 `de_main_dlg_flag[]` 经 `Pseudocode 28` 派生，而该标志只在 `b_dmx_de_cfg` 为真时传输，为假时沿用上一帧——它决定系数段的长度，沿用错了落点立刻偏移。对象数在两帧之间变化时显式报错，而不是拿错位的标志硬算。

**`audio_data_ajoc()` 已就位**：`6.2.3.4` 的完整外层，含 `b_some_signals_inactive`／`dmx_active_signals_mask`、两处 `oamd_dyndata_single()`、`b_dmx_timing`／`b_umx_timing` 与 `b_oamd_extension_present` 的跳过长度换算。至此 A-JOC 路径的音频数据从头到尾可解析。

core 与 full 的 timing 状态分别延续；只有 `b_derive_timing_from_dmx == 1` 时 full 模式才复用 core timing，否则使用 group 级 timing 或 full 自身历史。I 帧的块数必须非零，对象描述则按 `6.2.3.4` 固定将 LFE 放在信号 0。

判据是全链路落点：`var_channel_element()`、`ajoc()`、`ajoc_dmx_de_data()` 与两处动态数据串成一体，消耗的比特数必须等于构造长度。

**这一层暴露了落点判据的四类盲区**，五处注入里四处首轮全部通过。三处是覆盖不足（弱断言、分支未走到、状态污染场景不对），一处是判据本身无能为力——I 帧首块的 `b_no_delta` 在对象活动时两条路径**比特数恰好相同**，只有断言 `basic_info_status` 才区分得开。详见规范可追踪性 5.10。

两条分支按 M2 的探针结论显式拒绝：`b_static_dmx` 为真需要 `audio_data_chan()`（声道编码的下混），`b_alternative` 为真带备选对象数据集。

**真实码流当场纠出一条实现错误。** 该编码链每一帧都是 `b_dmx_de_cfg == 0`，即根本不带对话增强。原实现在没有历史配置时一律报错，导致一帧都解不下来。I 帧按 `4.5.2` 必须可独立解码，缺席的配置只能读作「没有对话对象」而非「未知」；非 I 帧上的缺席才是真正的沿用。见规范可追踪性 5.12。

M3 的逐对象位置与逐块更新至此解锁：两处 `oamd_dyndata_single()` 的信息块已逐帧解出；构造测试覆盖帧内多块，当前真实编码链则把源端多次更新降为每帧一次。

## M5：Direct-object 场景输出

交付物：

- direct-object PCM 与 OAMD 关联。
- bed 与对象共同输出。
- 首版 `Ac4SceneFrame` Rust API。
- 诊断渲染器或现有渲染器适配器。

退出条件：direct-object 测试流能够生成完整、时间对齐的渲染前场景。

**状态：进行中；A-JOC Core/Full 子集的场景数据契约与公开流式 Rust 入口已建立，正式边界由 [ADR-0007](decisions/0007-preprocessed-scene-rust-api-boundary.md) 冻结，真实 direct-object 验证仍受样本能力阻塞。** `macindecode-ac4-scene` 已定义容器无关的 timeline、presentation、bed/object PCM、group 级 OAMD common、帧内更新与诊断借用视图，并由 `decode_access_unit` 实现 `AutoUnique`/`Index`/`Id` 选择、Core/Full A-JOC 拓扑门禁、完整有界 AU 的 engine 失败策略以及带 AU/语法位置的结构化错误。`DecodeMode::Core` 使用同一 engine 的 `RequireCore` 出口取得 A-SPX PCM 与 downmix OAMD，并在控制入队前拒绝活动 dialogue enhancement；`DecodeMode::Full` 使用重建出口和 upmix OAMD。两者的 PCM/control 都随同一表 188 槽到期。公开 PCM 固定乘精确的 `2^-15`、不削波，独立报告 metadata active 与信号活动；事件保留 control source AU、raw timing/ramp 与 changed mask，按 `(offset, 码流顺序)` 排列并跨帧排队。只有 offset 0 更新进入帧起点状态；逐对象绝对生效时间相对码流顺序倒退时失败关闭。稳定配置复用 element/plane/common/metadata 容量，reset 清空状态与队列，显式 reset 换发且不复用 `SceneElementId`。M2 已判定现有编码链不产生 direct-object，该结论未被 IMS profile 的发现动摇——那批产物是 channel-based，同样不含 direct-object。

**后续方向：** 未定界字节流若要直接增量送入，应增加独立 sync/framing 或 incremental
ingestion API；跨配置代次若要延续应用侧 identity，应增加显式 generation/element remap。
两者都不得改变当前 bounded `AccessUnit` 的 payload 越界失败语义，也不得靠旧 ID、数组位置或
编码侧 object index 猜测同一对象；详细约束见 ADR-0007。

依据是 TOC 中 `ac4_substream_group_info()` 的 `b_ajoc` 标志，两个案例全部 143 帧一致（见测试向量策略 9.2a）。此前的疑虑同时被排除：参考解码器的 21 槽位容器并非固定值，而是码流声明的 `n_fullband_upmix_signals + LFE`。

因此按原定条款执行：**本阶段不得伪装成已覆盖 direct-object。** 该路径的缺口保留在支持矩阵中，重建工作直接进入 M6；解析侧的分支已由构造码流的单元测试覆盖，但那只是分支覆盖，不构成对真实 direct-object 码流的验证。

不依赖 direct-object 的交付物中，`Ac4SceneFrame` 数据契约与公开 `decode_access_unit` 已经建立，Session 也已自持并驱动借用输出的 A-JOC engine；Core 对象、Full 空间对象组、各模式原生 LFE、到期 group common、帧内 downmix/upmix OAMD 更新与跨帧更新队列均进入 Session 自有存储。CLI batch adapter 已把 `export-core-pcm`、`export-aspx-pcm`、`export-core-caf`、`export-adm-bwf`、`export-damf`、`export-objects-pcm`、`export-full-adm-bwf` 与 `export-full-damf` 迁到 Session，并在 Scene 外完成 sync/MP4 AU 适配与 edit 投影；需要 PCM 的出口另恢复旧 `±32768` 尺度及核心带/Core 诊断/Pseudocode 15 轨序，合成 ADM/DAMF 诊断渲染器则只保留已完整解码并完成控制对齐的场景元数据，不累积无用的整文件 PCM。core/full artifact 出口把所选 presentation 的对象描述、common、首份 warm-up 基线和 OAMD 更新时间线桥接给既有 writer，Core dialogue enhancement 仍在 Session 边界结构化拒绝。由于 direct-object 退出条件仍未满足，本阶段目前不能视为完成。

## M6：A-JOC full reconstruction

交付物：

- A-JOC payload 解析（已由 M4 的音频前端交付）。
- full 路径的 A-JOC 空间对象组重建，以及与 M4 core 对象输出的一致性。
- 对象 identity、工作区和跨帧状态定义。
- 按码率与案例分类的相关性、能量和串扰基线。

退出条件：单对象、多对象、运动对象和多码率案例均通过结构、元数据、信号和受控渲染验证。

**状态：完成。** A-JOC 量化数据与 core/full 元数据由 M4 解析；M6 已完成参数带、反量化、差分、rolling 插值、decorrelator/ducker 和对象矩阵，并把 A-JOC side information 与 A-SPX 控制一起通过表 188 FIFO 对齐到同源 QMF。full 路径随后执行对象重建、`Pseudocode 15` LFE 插回和独立终端 QMF 合成；256/448 kbps bed 向量均真实走过 wet 分支。`export-objects-pcm`、`export-full-adm-bwf` 与 `export-full-damf` 现消费 Scene Session 唯一的 normalized planar PCM，在 Scene 外乘精确的 `2^15` 恢复既有输出量级并应用 edit list；对象 WAVE 原子写出 Float32，full artifact 出口桥接 Full OAMD 后分别封装为 Standard BW64/Logic RF64/dbmd 或 DAMF home/3DoF。两种容器继续共用同一节目级增益和 S24LE writer。迁移后的对象 WAVE、full ADM 与 full DAMF 真实媒体基线均未重冻，既有 PCM、元数据与制品契约保持不变。

**crossover 的增益边界已按 [ADR-0006](decisions/0006-core-pcm-qmf-gain-boundary.md) 裁决。** 隔离 A/B 只把 Core IMDCT PCM 出口的 `×2` 从 QMF 前移到终端 QMF 合成后：core 直接交界比由 `-7.976 dB` 改善为 `-2.660 dB`，DRP 直接为 `-2.512 dB`；本地 20 对象由 `-8.105 dB` 改善为 `-2.898 dB`，DRP OAR 前为 `-2.524 dB`。低带端到端电平与时间轴不变，13.875 kHz 以上相对恢复约 `5.96 dB`。正式实现保留字面的 `Pseudocode 65/66`，以 `analyse_ac4_pcm`/`synthesise_ac4_pcm` 明示互逆表示换算；没有加入 crossover EQ、固定高频增益或 DRP 低通。该决策解决 P62/P64、5.5.3 与 P82 的量级矛盾，不冒充 ETSI 已发布的接口规则或勘误。

**DRP 的频谱参考另有硬边界。** 实测约 18.0 kHz 起陡降，约 18.375 kHz 起进入近停止带；因此 `>=18 kHz` 不用于裁决 A-SPX 带宽、幅度或 21 kHz 延伸，尤其不能把 18.375 kHz 以上的 DRP 静默当成规范目标。完整数值、处理开关与参考规则见 [A-SPX crossover 实验](experiments/aspx_crossover_normalization_observation.json)。

## M7：公共 ABI、性能与健壮性

交付物：

- 版本化 C ABI。
- Swift/C++ 最小集成示例。
- fuzz corpus、sanitizer/Miri 辅助检查和长时间稳定性测试。
- ARM64 与 x86-64 性能报告。
- 经过等价测试的局部 SIMD 内核。

退出条件：实时预算、内存上限、错误恢复和 ABI 生命周期均有自动测试；标量实现仍可作为独立参考路径运行。

**状态：进行中。** 2026-08-25 已完成 Apple M4 Pro ARM64 首份解码性能基线：普通 portable
release 构建覆盖 12 条真实 A-JOC 向量的 Core/Full 共 24 个组合，当前 Core 为
`11.64x`–`23.10x` 实时、Full 为 `5.22x`–`7.22x` 实时且均无 deadline miss；上一版数据捕获过
1 次 56.114 ms 的 Full 单 AU miss，新增观测已开始保留最差事件的 pass/AU 索引。完整预热后
复用 Session 的 24/24 组合均无 allocation、reallocation 或 deallocation。20 秒、1 ms 间隔的
热点采样显示当前主要成本在 A-SPX/QMF，Full 的次要成本在 A-JOC 重建。工具、完整方法、原始
JSON 和热点前十见[性能基线报告](PERFORMANCE.md)。首个 QMF 合成尾段融合候选虽保持逐位
一致，但五轮交替 A/B 仅提升 Full 标准 1500K `0.186%`，未达到 `5%` 保留线，已撤销。后续
符号级拆分进一步确认合成调制占 QMF 合成的 Core `96.57%`、Full `96.48%`，多相窗尾只有
`2.24%` / `2.08%`。随后按 [ADR-0008](decisions/0008-paired-qmf-synthesis-modulation.md) 保留
QMF 合成成对调制：共享负共轭输出行的一半乘法和相位加载，同时保持各输出原累加顺序。真实
Core、A-SPX、A-JOC PCM 全部逐位不变，24/24 项总时长与 p99 均改善；五轮 A/B 汇总 Core
提升 `20.94%`、Full 提升 `24.35%`，稳态分配继续为零。全套 after 捕获 1 次未复现的
60.310 ms wall-clock miss，定向复测 3,575 AU 为 0 miss，原始观测已保留在性能报告。
其上又保留纯 `no_std` 的 QMF 跨声道垂直 SIMD：两路 f64 lane 不做横向归约，仍维持各声道
原子带累加顺序；固定 PCM chunk 还消除了 ARM64 热内核中的越界 panic 慢路径。真实三层 PCM
逐位不变，五轮 A/B 的 24/24 项总时长与 p99 均改善，汇总 Core 再提升 `5.17%`、Full 再提升
`7.62%`，稳态分配仍为零。尚未设置自动性能门禁；x86-64 实测、公共 C ABI、fuzz 与长期稳定性
仍待后续。

## M4.5：Presentation/Metadata 解析闭环

**前五个 presentation payload 增量已落地。** `presentation_substream` 现按 P2
`6.2.2.3`/`6.3.3.1.1`–`6.3.3.1.15` 解析 presentation name 分片、target level、四类

没有该前缀。

12/28 比特的 advanced DE 原始参数；剩余保留 `add_data` 以精确 bit view 借用。拓扑按
Pseudocode 25 派生 OAMD timing 的 presence 条件。

envelope 之后固定的 7 比特 `dialnorm_bits` 与可选 `further_loudness_info(1, 1)` 现已解析；
共享响度结构保留 version 扩展、practice、dialgate/correction type、programme boundary、
全部量化响度码值、RTLL 与未定义 extension bit view。随后 5 比特
`drc_metadata_size_value`、presence gate 与 `variable_bits(3)` 扩展已解析，完整
`drc_frame()` 被严格定界并以无分配 bit view 保留；零长度、截断和长度溢出失败关闭。DRC
内部配置/逐帧数据仍未解析。其后按规范 `n_substream_groups` 解析 group-gain presence 与
`b_keep`，并以固定容量数组保留逐 group 六比特 `sg_gain` 原值；单 group 不错误消费 presence
bit，八 group 上限、截断和非法上下文均有构造门禁。当前只区分未传输、未携带、沿用上一帧和
新码值四种逐帧形态，尚不形成跨帧有效增益；associated audio 及更后 metadata 仍未解析，也不
执行响度归一化、DRC、group gain 或 advanced DE。

条件位、A-DE 两种长度、保留位边界与禁止越界借用后续 dialnorm，以及 further loudness 的
