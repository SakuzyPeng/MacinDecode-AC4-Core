# MacinDecode AC-4 Core v0.1.0

首个公开版本，提供 `macinac4` 命令行工具和 Rust 渲染前场景 API，用于检视 AC-4 码流，
并将已支持的动态 A-JOC 音频还原为对象 PCM、OAMD 和整数采样时间线。

## 主要功能

- 读取 MP4/M4A 中的 AC-4 sample 与 raw AC-4 sync frame，解析 presentation、group、
  substream、配置变化、随机访问以及容器 edit/priming 时间线。
- `inspect` 提供人读报告和 JSON；`--metadata-detail full` 在不重建 PCM 的情况下
  观察完整支持的元数据，区分 Core 布局声明、实际对象网格和派生扬声器布局。
- 动态 A-JOC Core/Full 解码串联 ASF、A-SPX、QMF、对象矩阵、去相关和 LFE 插回，
  提供带 OAMD 状态与更新的借用 Scene 视图。
- 导出 PCM WAVE、ADM BWF（BW64/RF64）、DAMF（0.5.1/0.6.0）和 Apple CAF。
  CoreCAF 仅接受通过固定网格及直接输出判据的 5.1、5.1.2、5.1.4、7.1.4 场景。
- 独立 `macindecode-ac4-metadata` 会话支持源 AU 观察、分区诊断和跨帧状态继承。
  核心库使用 `no_std`，需要存储的会话使用 `alloc`，禁止 `unsafe` Rust。
- 包含首发前修复：共享 OAMD 在局部失败恢复时只提交一次差分；等待随机访问期间
  的音频载荷仍计入 substream 码率。

## 下载与使用

所有二进制均启用 `audio-decode`，包含运行时需要的静态表；使用预编译工具不需要
安装 Rust 或另外下载规范文件。

| 系统 | 架构 | 附件 |
|---|---|---|
| Linux | x86_64 | `macinac4-v0.1.0-x86_64-unknown-linux-musl.tar.gz` |
| Linux | ARM64 | `macinac4-v0.1.0-aarch64-unknown-linux-musl.tar.gz` |
| macOS | Intel | `macinac4-v0.1.0-x86_64-apple-darwin.tar.gz` |
| macOS | Apple Silicon | `macinac4-v0.1.0-aarch64-apple-darwin.tar.gz` |
| Windows | x86_64 | `macinac4-v0.1.0-x86_64-pc-windows-msvc.zip` |
| Windows | ARM64 | `macinac4-v0.1.0-aarch64-pc-windows-msvc.zip` |

每个归档附有 `.sha256`，`SHA256SUMS` 汇总六个包的摘要。Linux 包使用 musl 静态链接。
macOS/Windows 包尚未提供商业代码签名，macOS 包尚未公证。

解压并将工具加入 PATH 后：

```bash
macinac4 --version
macinac4 inspect input.m4a
macinac4 inspect input.m4a --metadata-detail full --format json
macinac4 export-objects-pcm input.m4a --output objects.wav
macinac4 export-full-adm-bwf input.m4a --output full-adm.wav
```

成功输出使用 CLI JSON v1 envelope；`inspect` 默认人读文本，添加 `--format json`
可输出 JSON。参数错误返回 2，运行期错误返回 1，诊断写入 stderr。
命令和参数详见 [CLI 使用指南](https://github.com/SakuzyPeng/MacinDecode-AC4-Core/blob/v0.1.0/docs/CLI_USAGE.md)。

## 支持范围

- 当前终端 PCM/Scene 输出覆盖已验证的动态 A-JOC 长帧、A-SPX 子集。
  Channel-based/IMS 可检视拓扑和元数据，尚未接通 PCM 重建入口；direct-object
  尚无真实媒体验证和公共场景输出。
- 静态 A-JOC downmix、SIMPLE、短帧、分片或多倍帧率、高采样率扩展，以及活动
  dialogue enhancement、companding、A-SPX FIC/TIC 等未支持路径会返回结构化错误。
- 本工具提供渲染前场景，不执行最终扬声器/耳机渲染、响度管理或 AC-4 编码。
- ADM/DAMF 导出可能无法等价表达部分 AC-4 空间或耳机元数据；这类损失会通过
  `mapping.lossy` 等结构化诊断报告，不能把导出容器理解为全部元数据的无损转换。
- 三阶段真实 PCM 基线用于验证回归一致性，不等同于 Dolby conformance 或认证。
  更完整的支持矩阵见 [路线图](https://github.com/SakuzyPeng/MacinDecode-AC4-Core/blob/v0.1.0/docs/ROADMAP.md#音频重建与-corefull-场景输出支持矩阵)。
- Rust API 处于 0.x 阶段，C ABI 尚未提供。源码构建要求 Rust 1.98；启用
  `metadata-decode` 或 `audio-decode` 时须按仓库说明在本地准备锁定的 ETSI 表。
